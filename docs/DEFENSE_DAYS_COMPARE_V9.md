# BETA 0.9 — 날짜별 수비 평가·근거 비교

## 저장 계획과 데이터 보존

기존 v0.8 구현을 확장한다. 수비 상황 원본, 회차별 타격 기록과 수정 이력, 수동 기능점수, 경기 이벤트 및 사진을 변환하거나 삭제하지 않는다. RULE01~08, TYPE1/TYPE2, 9능력 가중치 v2.0, 주루40:60 및 타격 전체 유효 회차 평균을 유지한다.

Workspace schema9에 defenseDays와 comparisonSelection만 추가한다. defenseDays는 날짜·공통 평가자·목적·메모·참여 학생 ID 순서·생성 시각을 저장한다. 기존 수비 기록은 원래 날짜로 계속 조회하고, 새 날짜 그룹을 소급해서 만들지 않는다. comparisonSelection은 학생 ID·메모·수정 시각·status:draft인 감독 검토 후보이다. 공식 선발 결과가 아니다.

v8→v9는 기존 값을 유지하고 두 새 필드를 빈 배열/null로 시작한다. v8 원문 전체는 migrationSource.raw, 기존 기기 키는 그대로 보존한다. 검증/경기 재생/참조 검사 후 v9 키에 단일 저장한다. 실패 시 기존 키를 변경하지 않는다. v1~v9 JSON 읽기, v9 내보내기를 지원한다. 구버전 탭의 후속 변경과 현재 revision 충돌을 검사한다. 사진 IndexedDB 및 암호화 백업 계약은 동일하다.

학생 완전삭제는 해당 날짜 참여자·후보 참조도 정리한다. 평가 또는 전체 기록 초기화는 날짜 그룹·후보도 비우며, 경기만 초기화하면 유지한다. 기존 백업/명시적 실행 확인 절차를 유지한다. 자동 다운그레이드·동시 쓰기 원자적 잠금·서버 동기화는 제공하지 않는다.

## 현장 조작

| 작업 | 이전 | 이번 변경 |
|---|---|---|
| 수비 준비 | 학생마다 날짜·평가자 지정 | 날짜/공통 설정 1회 후 학생 여러 명 선택 |
| 다음 학생 | 저장 후 학생 선택 | 저장·다음 학생 1회 터치; 실패하면 그대로 유지 |
| 수비 점수 확인 | 학생마다 프로필 조회 | 당일/누적 전환 1회, 전체 학생 9항목 비교 |
| 체크 점수 적용 | 학생마다 출처 선택 | 관찰한 날짜 참여자 누적 체크 점수 일괄 적용 1회 |
| 타격 상세 기록지 | 계속 펼쳐져 입력 폭 점유 | 기본 접힘; 보기/숨기기 각각 1회 |
| 비교 후 경기 편성 | 학생별 조회 후 다시 선택 | 후보 저장 → 새 경기에서 불러오기 → 팀 배정 |

터치 수는 위 작업별 조작 수이며 학생 수·관찰 항목 수·확인 동작에 따라 전체 입력 수가 달라진다. 점수나 관찰을 자동 생성하지 않는다. 다음 학생은 미관찰 상태에서 시작한다. 미저장 기록이 있으면 날짜·학생·메뉴 이동을 막는다. 마지막 학생 저장 후에는 이동하지 않고 추가 상황을 입력할 수 있다.

개인별 이전 수비 기록 화면을 유지한다. 날짜 그룹의 학생들도 같은 수비 원본 및 정정 이력을 사용한다. 날짜별 비교는 해당 날짜의 최신 유효 기록, 누적은 모든 날짜의 유효 관찰을 사용한다. 점수 일괄 적용은 누적 출처 선택이며 기존 수동 점수를 덮어쓰지 않는다. 측정하지 않은 능력은 미측정이다.

## 근거 비교와 선택

- 타격: 직접/상세 기능점수 출처, 유효 횟수·날짜·최근 변화, 정타/강한 타구/정상/파울/헛스윙 비율, 방향·9구역·유형·강도 분포.
- 실전: PA·AB·H·HR·총루타·타율·장타율·삼진·득점·기록된 RBI/FC, 수비 관찰 성공률·PO/A/E·포지션/실책/능력별 관찰 분포.
- 수비: 적용 출처별 9능력 점수/관찰 횟수, 기존 TYPE1 가중치 적합도. 필요한 능력이 없으면 적합도는 미측정이다.
- 실전은 삭제하지 않은 모든 경기의 기록 통계이며 미완료 이닝도 포함한다. 이는 선발 통계 정책의 확정이 아니다. 타율/장타율은 경기별 비율 평균이 아닌 전체 합계 H/AB, 총루타/AB이다. 실전 PA에 기능평가를 더하지 않는다.
- 상대 장점/보완점은 같은 지표·출처·단일 배점에서 최소 관찰 수를 충족한 학생 평균과의 차이이다. 기본 최소 수는 기존 타격 설정(초기15)을 사용하며 이 화면에서 조정한다. 공식 합격선이 아니다. 수동 점수·여러 배점 혼합·표본 부족은 판단 보류한다.
- 관찰 건수 자체나 타구 방향은 좋고 나쁨으로 단정하지 않는다. 점수와 비율 간 차이를 합산하거나 크기로 순위를 매기지 않는다. 최종 영역 비율/타격·수비 기능40:실전60은 미확정 상태다.
- 감독이 검토 후보를 저장한다. 새 경기의 불러오기는 체크만 하며 팀 배정/10명 엔트리/수비 배치/감독 확인을 자동 수행하지 않는다.

## 검증 및 남은 확인

npm run check와 임시 브라우저 컨텍스트의 WebKit/Chromium 검증을 수행한다. 실제 학생/실사용 저장소는 사용하지 않는다. 가상 v8 이전, 날짜 먼저 저장/새로고침, 2명 평가, 저장 실패/재시도, 다음 학생 초기화, 9항목 적용, 비교 후보 저장/경기 불러오기, 타격 기록지 접기/초안 유지, 가로 넘침을 확인한다. 실행 결과는 VALIDATION.md에 기록한다.

실제 iPad Safari/홈 화면 앱의 키보드·가로세로 전환·연속 수업 입력은 추가 확인이 필요하다. 공식 수비 수행 기준/배점·최소 표본·실측 환산·종합 선발 알고리즘, 서버 인증/권한/동기화는 계속 TODO다. 비교 화면의 기간 필터·후보 변경 이력·날짜 그룹 설정 정정 UI는 아직 제공하지 않는다. 원본 평가 기록의 수정/취소 이력은 기존대로 보존한다.
