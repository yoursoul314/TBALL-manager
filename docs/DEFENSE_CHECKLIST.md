# 수비 상황 체크리스트 v1 · 시범안

2026-10-27 요청에 따른 수비 기능평가 확장. 기존 9능력·TYPE1 v2.0·RULE01~08·주루40:60 및 최종 종합 선발의 미확정 상태를 유지한다.

## 기록 흐름

기능평가 & 팀워크 → 수비 체크리스트 → 등록 학생·날짜·평가자 → 상황 → 행동 결과 → 저장·다음 상황. 땅볼/뜬공/송구 받아 처리/송구 연습/베이스·태그/복합 수비 상황을 제공한다. 상황에 필요한 항목을 먼저 보여주고 나머지 9능력은 펼칠 수 있다. 상황 변경은 이미 체크한 관찰을 지우지 않는다. 다음 상황 저장 후 모든 관찰과 실책·메모는 초기화하고 날짜·평가자·배점만 유지한다.

각 능력은 성공 / 부분 수행 / 실패 / 기회 없음 / 미관찰(null) 중 하나. 땅볼 포구 성공 후 악송구는 G 성공 + A 실패로 각각 기록한다. 공을 놓쳐 송구 기회가 없으면 A 기회 없음을 명시한다. 미선택 송구를 자동 실패로 만들지 않는다. 다른 선수의 후속 포구는 해당 학생을 선택해 별도 상황으로 기록한다. 실전 경기의 자살·보살·공식 실책을 자동 생성하지 않는다.

## 시범 점수

기본 제안은 성공2 / 부분1 / 실패0이며 사용자가 조정할 수 있다. 성공 > 부분 ≥ 실패 ≥0, 성공은 양수. 관찰별 환산 = 해당 결과 배점 / 성공 배점 ×100. 능력별 점수 = 모든 유효 관찰별 환산점 합 / 해당 능력의 유효 관찰 수. 날짜별 평균을 재평균하지 않는다. 반올림은 표시 단계만 소수1자리. 미관찰·기회 없음·취소는 제외하고 분모0은 미측정이다.

예: G 성공3·부분1·실패1 → (6+1)/10×100 =70점. A 성공1·실패1 →50점. 실책 분류는 설명 자료이며 추가 감점하지 않는다. 결과별 빈도와 유효 횟수도 함께 표시해 적은 관찰로 능력을 단정하지 않는다. 배점 변경은 기존 기록을 소급 변경하지 않으며 서로 다른 배점이 섞이면 경고한다.

통일된 실측 환산표가 확정된 것은 아니다. 사용자 후속 지시에 따라 체크 점수를 최종 수비 기능평가9항목에 적용할 수 있다. 학생별로 '체크 점수를 수비 기능평가에 적용'을 누르면 기능평가 화면의9항목, 선수 명단의 적합 포지션, 경기 엔트리의 추천/적합도, 선발 시뮬레이션 모두 같은 체크 기반 능력 점수를 사용한다. 이후 관찰 정정·취소는 자동 재계산한다. 기존 수동 Assessment.abilities는 변경하지 않고 '기존 수동 수비평가로 전환'으로 복귀할 수 있다.

점수 출처는9항목 전체에 적용한다. 체크 미측정 항목을 수동 점수로 임의 혼합하지 않는다. 필요한 능력이 없는 포지션은 기존 positionScore 규칙대로 추천 불가이며, 가중치0인 능력만 생략 가능하다. 최종 종합 선발 알고리즘·타격/수비 기능과 실전 비율은 여전히 TODO다. 적용한 수비 기능 점수는 실전 타석·안타·수비 성공률에 합산하지 않는다.

## 저장·호환성

출시 전 스키마8에 defenseAssessments와 defenseEvaluationChoices 배열을 추가한다. v1~7은 빈 배열로 이전하며 기존 원문·수동점수·경기·타격 평가를 보존한다. 체크리스트가 없는 초기 v8 로컬 검증본도 빈 배열로 읽는다. JSON 및 사진 암호화 백업은 새 배열을 포함한다.

DefenseAssessment는 id/playerId/createdAt와 append-only revisions를 가진다. 각 revision은 id/date/situation/9개 observations/error/note/assessor/rubric/status/changedAt/changedBy/reason의 완전한 스냅샷이다. 첫 revision이 원본이고 정정·취소는 새 revision을 추가한다. 변경 전후는 인접 스냅샷으로 보존한다. 잘못된 학생 참조·중복 ID·역행 시각·배점·관찰값은 복원 검증에서 차단한다. 저장 실패 시 입력과 원본을 유지한다.

평가/모든 기록/전체 초기화는 체크 이력도 지운다. 경기만 초기화는 유지한다. 선수 완전삭제는 선택 학생의 체크 이력만 제거하고 삭제 미리보기에 수량을 표시한다. 팀 완전삭제는 독립 학생 평가를 유지한다.

## 미확정·추가 검증

부분 수행의 통일된 판정 사례, 거리·타구 속도별 난도 보정, 통일 배점 확정, 최소 표본/성장 판정 기준은 TODO다. 수비 기능 점수 출처는 학생별 명시 선택으로 확정하며 출처 변경 이력을 id/playerId/source/changedAt/changedBy로 보존한다. 이번 시범안은 수업에서 사례를 수집하고 기준을 검토하는 용도다. 실제 iPad 키보드·손가락 조작은 기기 확인이 필요하다.


## 현장 입력과 변경 파일

수비 기록 집중 모드는 학생 이름·날짜·상황·행동 체크·저장 버튼을 크게 보여주고 분석/출처 설정/이력을 숨긴다. 기본 땅볼 상황에서 포구와 송구 두 항목을 선택하면 저장까지3터치이며, 상황 선택이 필요하면4터치다(날짜·평가자 최초 설정 제외). 모든9능력은 펼쳐 입력하고 후속 송구를 하지 않았다면 기회 없음을 체크한다. 부분 수행 판정은 감독이 직접 하며 시스템이 추정하지 않는다.

주요 파일: domain/defenseAssessment.ts(모델), data/defenseAssessmentSchema.ts(검증), assessment/defenseChecklist.ts(저장·집계), evaluation/defense.ts(9항목 출처 선택), components/DefenseAssessmentPanel.tsx(체크·출처·이력·분석). 기존 AssessmentView/Players/NewGame/SelectionView를 연결하고 스키마·초기화·완전삭제·백업을 확장했다. 자동 테스트는 defenseChecklist.test.ts, defense.test.ts, DefenseAssessment.test.tsx이며 브라우저 시나리오는 scripts/defense-assessment-qa.cjs다.
