# v1 → v2 데이터 보존 계획과 구현 계약

- RULE01~08 및 TYPE1 v2.0 설정 파일은 변경하지 않는다.
- v1 저장 키 `tb-manager.workspace.v1`을 삭제/덮어쓰지 않는다. v2는 `tb-manager.workspace.v2`에 저장한다.
- 최초 로드: JSON 파싱 → v1 스키마 검증 → 새 모델 변환 → 참조 및 전체 경기 재생 검증 → v2 저장. 검증/용량 오류 시 쓰기를 중단하고 원본 복구 다운로드를 제공한다.
- v2의 `legacySource`에 v1 원문을 그대로 보관한다. v1 이벤트 ID, 순서, 시각, payload 및 기존 팀워크 관찰은 변경하지 않는다. 원문에는 알 수 없는 확장 필드도 보존된다.
- v2 원문과 보존된 v1 키가 서로 다른 경우, 구버전 탭의 후속 쓰기일 수 있으므로 저장을 막고 두 원문을 다운로드하도록 안내한다. 복원으로 v1 출처가 달라지는 경우 현재 브라우저 v1 키를 별도 보존해 충돌 검사 기준으로 삼는다.
- 기존 타구 방향과 quality(타구 유형)는 유지한다. 거리·강도·타점·실책 판정은 추측해서 채우지 않는다. 누락 항목은 미기록이다.
- 모든 v1 팀워크 항목(책임감·존중 포함)은 `legacyTeamwork`로 이동하여 원래 분류·점수·관찰자를 보존한다. 새 기회/수행 결과와 합산하거나 자동 환산하지 않는다.
- 백업 v1과 v2를 모두 읽는다. 새 백업은 v2이며 legacySource/legacyTeamwork와 원본·수정 이벤트 전체를 포함한다. v2를 v1로 역변환하지 않는다. 구버전 앱에서 v2 백업을 열 수 없다는 점을 UI에 표시한다.
- 과거 플레이 수정은 REVISE_PLAY 이벤트(대상 원본 ID, 교체할 payload, 사유, 작성자, 시각)를 추가한다. 원본 배열은 불변이다. 전체 재생으로 후속 주자·타순 충돌을 검사하여 충돌 시 수정 저장을 거절한다.
- 기존 중복 타격 등 규칙과 모순되는 데이터는 자동 삭제/점수 보정하지 않는다. 원문을 보존하며 복구 오류로 알린다. 복구 도구/여러 플레이 일괄 정정은 TODO.
- 외부 파일 백업을 별도로 보관해야 브라우저 데이터 삭제에도 복구 가능하다. localStorage의 교차 탭 원자성, IndexedDB 트랜잭션, 서버 인증/권한/암호화/동기화는 TODO.

## 릴리스 검증

마이그레이션 반복 실행, 백업 v1/v2 왕복, 알 수 없는 버전, 잘못된 참조, 용량 초과, 구버전 탭 변경, 수정 후 전체 재생을 자동 테스트한다. 실제 학생 데이터는 테스트/저장소/배포 샘플에 사용하지 않는다.

## v3 날짜별 타격 평가 이전 계획 및 구현

- 읽기/쓰기의 현재 키는 `tb-manager.workspace.v3`이다. 기존 v1/v2 키를 삭제하거나 덮어쓰지 않는다.
- v3가 없으면 v2 우선, 없으면 v1을 읽고 기존 스키마/선수 참조/전체 경기 재생을 검증한 후 이전한다. v2의 v1 기준본 충돌도 먼저 검사한다.
- v1은 기존 legacySource.raw, v2는 migrationSource.raw에 입력 원문을 보관한다. 원문에는 알려지지 않은 확장 필드도 포함된다. 기존 Assessment.battingSkill, 경기 이벤트, 책임감·존중 기록은 변환하지 않는다. 새 세션/회차/감사 배열은 빈 배열이며 가상의 평가 횟수를 만들지 않는다.
- v3 전체 검증 후 한 번의 setItem으로 새 키를 쓴다. 용량 부족/검증 실패 시 이전 키는 그대로 남으며 성공을 표시하지 않는다. 복구 파일에는 v1/v2/v3 원문이 각각 들어간다.
- v3 저장 시 v1/v2 원문 기준본을 기록한다. 구버전 탭이 이를 바꾸면 쓰기를 중지하고 복구를 안내한다. 기존 리비전 검증과 storage 이벤트 감지도 세 버전 모두 적용한다. 동시 쓰기 원자적 잠금은 계속 TODO다.
- JSON 입력은 버전1/2/3, 출력은 버전3이다. 버전과 내부 스키마가 달라지거나 중복 회차, 잘못된 점수/날짜/참조, 끊어진 감사 이력, 최종 행과 다른 이력이 있으면 복원하지 않는다. 현재 데이터를 먼저 백업하는 기존 복원 UI를 유지한다.
- v3는 구버전 앱에서 열 수 없다. 배포 롤백 시 v1/v2 보존본은 남지만 v3 이후 신규 평가가 포함되지 않으므로 v3 JSON을 별도 보관하고 최신 버전에서 복원한다. 구버전 저장본을 다시 쓰거나 현재 v3를 강제로 지우는 자동 다운그레이드는 제공하지 않는다.
- 원문·이력을 중복 보관하므로 localStorage 용량을 더 사용한다. 기존 10MB JSON 입력 제한은 유지한다. IndexedDB/서버 저장, 인증·접근 권한, 암호화 백업과 자동 병합은 TODO다.
