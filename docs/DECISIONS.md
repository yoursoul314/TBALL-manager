## 확정 평가 비율

- 주루 = 기능평가 40% + 실전 60%.
- 실전 점수 환산법은 아직 미확정이므로, 이 비율이 확정되었다고 주루 종합 점수를 자동 생성하지 않습니다.

## 구현상의 초기 선택 (경기 규칙 추가가 아님)

- 서버 인증 전 실제 학생 개인정보를 입력하지 않음. 표시 이름은 별칭·가상 데이터 사용.
- 처음에는 가상 2팀 24명. 기본 출전 타순은 각 팀 10명, 벤치 2명.
- 초기 경기 생성 UI의 자동 앞10명 선택은 v0.5에서 감독 직접 선택·위/아래 타순 편집으로 교체. 드래그 편집은 제공하지 않음.
- 이닝 입력 1~20은 UI/저장 유효성 범위이며 경기 규칙의 최대 이닝 확정값이 아님.
- 공통 완료 이닝 0개로 종료하면 승패 판정 없음. 미완료 점수로 승자를 정하지 않음.
- 정식 교체는 같은 타순 자리, 해당 선수가 주자인 경우 베이스, 수비 자리를 승계.
- 추천 알고리즘은 10포지션의 적합도 합계 최대화. 동일 최댓값은 입력 순서에 따라 결정(경기 실력의 우열 선언 아님).
- 감독 승인 UI는 **시범 수비 배치** 승인. 최종 종합 선발 승인과 분리.
- 저장 후 데이터가 바뀌면 배치안을 오래된 것으로 표시하고 재시뮬레이션 요구.
- 초기 localStorage 리비전 비교는 충돌 탐지 보조책. 동시 쓰기 원자성은 제공하지 않음.

## 초간편 UI v2.0 결정

- 간편 모드는 기본값. 결과·점수는 필수, 방향은 선택, 정밀 관찰은 접힌 상세 모드. 누락된 관찰은 성공/실패/평균값으로 추정하지 않는다.
- 좌·중·우만 선택한 평가의 거리는 null. 기존9구역은 변경하지 않는다. 기존 감사 스냅샷의 필드를 소급해서 채우지 않는다.
- 경기 이동 제안은 주자별 확인이 필요하다. 아웃 종류·위치 및 심판 타임을 자동 확정하지 않는다. RULE01~08은 유지하며 엔진 변경은 이벤트 버전3 허용만 포함한다.
- 홈런 타구 질의 궤적·강도 분류는 상세 모드에 그대로 유지한다. v2.0의 선택 관찰 원칙에 따라 미관찰 홈런도 null로 기록 가능하다.
- 수비 난도는 감독의 선택 관찰이고 평가 환산 기준을 뜻하지 않는다. 주루40:60, TYPE1 v2.0, TYPE2 참고용, 9능력 및 모든 미확정 평가 정책은 유지한다.

## 학생·엔트리·공수 통합 기록 v3 결정 (2026-10-26)

- 학년은 선택적1/2/3 또는 null. 학생 ID와 학년·반·번호, 팀은 독립적이다. 기존 학년은 추정하지 않는다.
- 새 경기의 선발은 팀당10명, 교체 후보는 roster에만 포함한다. 미출전·결석·출전 불가를 별개 상태로 보존한다. 이전 경기의 기존 인원·타순은 강제로10명으로 변환하지 않는다.
- 경기 생성 당시 이름·등번호·팀·출전 상태·초기 수비는 Game.entry에 보존한다. 이후 정식 교체/수비 변경은 기존 이벤트로 재생한다. 사진은 현재 학생 ID의 기기 저장 사진이며 과거 사진 사본은 만들지 않는다.
- playedOn은 현지 달력 날짜 문자열, createdAt은 UTC 생성 시각. 이전 경기의 createdAt 날짜 부분은 추정값으로만 표시하며 감독 확인/정정 이력을 남긴다.
- 수비 기능 추천은 기존 TYPE1 v2.0 최적 배치 초안. 감독은 선수·타순·배치를 바꾸고 별도로 확인한다. 최종 종합 선발 정책을 확정하지 않는다.
- 수비 연결은 실제 state.defense만 사용한다. 관찰만으로 아웃·실책을 만들지 않는다. 포스/태그아웃 또는 명시적 뜬공 아웃에는 대상 주자·베이스가 필요하다. 성공 송구 중 동일 목표 아웃에 연결된 수비수를 보살 후보로 제안하고 감독이 확인/해제한다.
- 수비 행동은 G/F/C/A/B 관찰만 명시적으로 생성한다. L/Q/M/J와 난도는 상세 화면의 독립 관찰로 남으며 자동 추정하지 않는다. 주자 확인과 심판 타임을 생략하지 않는다.
- 사진은 IndexedDB 로컬 Blob. 업로드8MB, 저장320px·200KB 제한은 저장 운영 기준이다. 원본 사진·위치 메타데이터는 저장하지 않는다. 사진 포함 백업은 PBKDF2-SHA256 600000회 + AES-256-GCM으로 암호화한다. 서버 인증과 기기 저장소 자체 암호화를 구현한 것으로 해석하지 않는다.
- RULE01~08, TYPE1/TYPE2,9능력 가중치, 주루40:60, 날짜별 타격평가 가중 평균은 변경하지 않는다.

## iPad 저장·조작 호환성 v0.5.1

- 사진의 IndexedDB 저장 표현만 바꾼다. 이전 Blob은 보존하며 신규 ArrayBuffer 행을 읽을 때 Blob으로 복원한다. JSON 및 암호화 백업 계약, 학생 ID 연결, Workspace schema5는 유지한다.
- 수비 필드의 버튼 좌표/높이는 화면 표현이다. TYPE1 포지션 정의·가중치 및 RULE01~08 파일은 수정하지 않는다.
- 실제 학생의 이름/사진을 QA에 사용하지 않는다. 일반 앱 모드를 새 임시 컨텍스트에서 시험하여 실제 IndexedDB·새로고침을 검증한다. 실기 iPad Safari의 키보드·사진 보관함·홈 화면 설치는 별도 수동 검증 항목이다.

## v0.6 목록·현장 화면 결정

- 경기·팀 삭제는 복원 가능한 논리 삭제로 구현한다. 영구 삭제 및 이벤트/선수/사진 연쇄 삭제는 하지 않는다. 삭제된 경기는 기본 경기 집계에서 제외한다. 팀만 삭제한 경우 기존 경기는 계속 조회한다.
- Team/Game archivedAt 및 archiveHistory를 schema6에 추가하고 v1~v5 원본 키·JSON 읽기를 유지한다. 사진 저장·타격 평가 원본은 그대로다.
- 경기 기본 기록의 주자 확인/심판 타임 및 RULE01~08, TYPE1/TYPE2 가중치는 변경하지 않는다. 화면 공간은 상세 이력을 접고 독립 기록 영역을 사용해 확보한다.
- 타격 평가 상세 모드는 같은 초안을 전체 화면에서 편집한다. 기존 회차별 직접 점수와 전체 유효 회차 가중 평균을 변경하지 않는다. 확정되지 않은 종합 선발/환산 정책은 계속 TODO다.

## BETA0.7 사용자 후속 요청 (2026-10-26)

학생은 팀 없이 등록하고 경기 생성 때 불러와 팀에 배정한다. 기존 teamId는 이전 소속 참고로 보존한다. 신규 학생에 임의의 팀을 부여하지 않는다. 등록/삭제 명단과 평가 선택을 연결하며 선수 삭제는 원본 보존 방식이다.

초기화는 기록만/선수·팀·사진 포함 모두 지원한다. 백업과 명시적 실행 확인 없이 실제 데이터를 비우지 않는다. 앱 업데이트도 저장되지 않은 초안을 확인한다. 선수/팀/사진/스키마 변경은 경기 규칙 또는 선발 정책 변경을 의미하지 않는다. 상세 계약은 MANAGEMENT_V7.md 참조.

## BETA0.8 후속 요청 (2026-10-26)

학년·반 필터/다중 팀 배정, 날짜 생성 후 여러 학생 평가, 사진 표시 비율 보완을 적용한다. 사용자는 과거 기록에 연결된 팀/선수를 완전삭제할 때 연결 경기·평가도 함께 삭제할 수 있도록 명시적으로 선택했다. 삭제 전 경기 전체 영향과 개수를 표시하고 암호화 백업과 확인 문구를 요구한다. 팀을 완전삭제해도 등록 학생과 독립 평가는 유지한다. 일반 삭제·복원은 계속 원본 보존 방식이다. 규칙·평가 가중치는 변경하지 않는다.
