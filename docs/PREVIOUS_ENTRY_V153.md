# BETA 0.15.3 · 지난 편성 불러오기와 희망 포지션

## 사용 순서

1. 새 경기 → **지난 경기 편성 불러오기**를 펼치고 경기를 선택한다.
2. 당시 시작 편성의 양 팀·주장·선발·후보·타순·수비 위치를 새 초안으로 불러온다. 경기명·경기 날짜·시작 시간은 현재 새 경기 입력값을 유지한다.
3. 당일 출전 상태를 확인하고 주장, 학생, 타순의 위·아래 버튼, 수비 위치를 직접 수정한다. 주장 변경은 직접 구성과 랜덤 구성 모두에서 가능하다.
4. 감독 확인 후 새 경기를 만든다. 과거 경기 원본과 이벤트는 변경하지 않는다.

0.15.2까지의 앱은 경기별 주장을 저장하지 않았다. 그런 경기에서는 주장 미지정과 안내를 표시한다. 타순 첫 번째 학생이나 소속 팀을 근거로 주장을 추측하지 않는다. 새 버전에서 생성한 경기부터 당시 주장을 다시 불러올 수 있다.

삭제된 경기는 불러오기 목록에서 제외한다. 삭제된 팀의 경기는 팀 복원이 먼저 필요하다. 삭제된 선수는 제외하고, 현재 출전 불가 선수는 선발에서 빼고 출전 불가 상태로 표시한다. 결석·미출전 등 지난 상태는 표시를 유지하므로 당일 상황에 맞게 직접 바꾼다. 선발이 부족하면 보충하기 전 생성을 막는다. 경기 종료 시 교체된 최종 배치 대신 **시작 당시 엔트리**를 사용한다.

## 희망 포지션 반영

랜덤 구성에서 **희망 포지션 반영**을 선택한 뒤 구성 적용을 누른다. 학생 등록에 저장된 `pref1`·`pref2`만 사용하며 수비 능력 점수·희망 가산점은 사용하지 않는다.

- 먼저 기존 방식대로 선발 20명과 교체 후보를 뽑는다. 희망 유무 때문에 학생을 후보로 내리거나 선발로 올리지 않는다.
- 단순 랜덤: 주장은 각 팀 선발로 고정하고 나머지 선발의 팀·수비 자리를 조정한다.
- 실력 균형: 기존 점수 기반 팀 구성을 그대로 유지하며 각 팀 안의 수비 자리만 조정한다. 균형 구성 자체의 기존 점수 비교 방식은 유지한다.
- 전체 1지망 충족 인원을 우선 최대화하고, 그 조건 안에서 2지망 충족 인원을 최대화한다. 같은 조건은 무작위 순서로 결정한다. 지망이 겹치거나 없으면 남는 자리에 배정하며 희망이 모두 충족된다고 보장하지 않는다.
- 구현의 우선순위 비용 21:1은 20자리의 1지망 우선 조건을 표현하는 내부 값이다. 평가 점수나 학생 등급에 더하지 않는다.
- 타순은 평가나 희망 순위가 아니다. 남아 있는 같은 팀 학생의 상대적 순서를 유지하고 새로 온 학생을 이어 붙인다. 감독이 직접 조정할 수 있다.
- 1지망/2지망 충족·미충족·미설정 인원을 표시하고 수동 수정 시 다시 계산한다.
- 선택 항목은 기본 꺼짐이다. 설정만 바꾸어 현재 초안을 자동 변경하지 않으며, 다시 구성 적용을 눌러야 반영한다.

## 저장·백업 계약

현재 schema15, JSON 백업 v1~v15 읽기 및 v15 쓰기. 저장 키 `tb-manager.workspace.v12`는 그대로 유지한다. `Game.entry.captains?: { away: Id | null; home: Id | null }`를 추가한다. 과거 필드 부재는 미기록, 새 경기 null은 감독이 미지정한 상태다. 주장은 해당 팀 선발에 있어야 하며 중복 선수 검증도 그대로 적용한다.

v14 → v15는 선택적 필드 추가이므로 이전 경기·선수·평가·사진·수정 이력을 수정하지 않는다. 전체 v14 문서를 새 중첩 원문으로 복제하지 않아 저장 공간 증가를 피한다. 기존 원문 보관 필드는 유지한다. 전체 검증 후 한 번의 저장으로 교체하며 저장 실패 시 이전 원문을 그대로 남긴다. 공간 복구 보관본의 v14 입력도 동일하게 이전한다. 구버전 앱은 v15 백업을 읽지 못하므로 복원 시 BETA 0.15.3 이상을 사용한다.

주장과 실제 엔트리는 저장하지만 편성 방식·난수 시드·희망 일치 요약은 별도 저장하지 않는다. 팀의 영구 주장 직책도 만들지 않는다. 원본 경기의 이벤트, RULE01~08, TYPE1 v2.0, 주루40:60, 날짜 평가 누적 평균 및 최종 종합 선발 미확정 정책은 유지한다. 서버 개설은 계속 보류한다.
