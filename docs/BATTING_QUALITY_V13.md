schema11→12, 새 키 tb-manager.workspace.v12. v1~v11 원문은 그대로 보존하고 검증 후 한 번에 기록한다. 사진 저장소·경기 이벤트·확정 경기 규칙·수비 가중치는 변경하지 않는다. JSON1~12 복원 지원. 기존 타격 세션/회차/감사 이력에 새 점수를 역산하지 않는다. rubricVersion 부재는 기존 manual-ten-v1로 해석한다. 새 날짜/세션은 quality-six-v1을 명시하고 원점수와 선택 등급을 함께 저장한다. 기존1~10점과 새−1~5점의 원점수 평균은 혼합하지 않는다. 새 유효 기록이 있으면 신규 척도를 우선 사용하며 이전 척도는 별도 조회한다. 다른 척도의 선수 간 자동 우열 판단은 보류한다.

## 확정한 이번 척도
5 장타성 정타(배럴),4 정타(강한 땅볼/단타),2 약한 땅볼,1 팝업,0 일반 파울,−1 티 타격/헛스윙. 3점은 없다. 전체 유효 회차 원점수 합/횟수로 평균을 내고 사용자 승인에 따라 (평균+1)/6*100 환산한다. 0과−1은 유효 점수, null만 미측정이며 취소 회차·세션은 제외한다. 기존 수동1~10점은 평균*10을 유지한다.

## 항목 판단
강도와 정타 정확성은 새 질 척도의 판정 내용과 중복되므로 신규 입력에서 제거한다. 기존 원본은 보존한다. 궤적인 타구 유형은 같은4·5점 안의 땅볼/직선타/뜬공을 구분할 수 있어 접힌 선택 관찰로 유지한다. 유형·방향은 점수에서 자동 추정하지 않는다. 9구역 지도는 유지한다. 티 타격/헛스윙은 합친 항목으로 기록하며 헛스윙만으로 통계를 표시하지 않는다.

[MLB의 타구 궤적 정의](https://www.mlb.com/glossary/statcast/launch-angle), [배럴 정의](https://www.mlb.com/glossary/statcast/barrel)는 구분 참고 자료다. 여기의 배럴은 수업용 관찰 명칭이며 MLB의 속도·각도 실측 판정으로 취급하지 않는다. 6단계는 제공된 척도이며 학교 수업에 대한 검증된 표준으로 주장하지 않는다.


## 펑고·배치 확장 (사용자 추가 지시)

선수 pref1/pref2는 기존 주·보조 포지션과 별개인 optional nullable 값이다. 과거 선수에 희망을 추정하지 않으며 동일 지망 중복 입력은 막는다. 별도 fungoDays(date/assessor/playerIds), fungoAssessments(id/playerId/revisions)를 추가한다. 기존 날짜·선수·평가는 손대지 않는다. 날짜+학생당 하나의 기록이며 정정 시 원본 전체 스냅샷을 revisions에 추가한다. 취소도 이력으로 보존한다. JSON 복원, 선택 초기화, 선수 완전삭제의 기존 확인 절차에 새 자료를 포함한다.

간편 모드의 5구 기본 상황은 G/G/F/C/G이며 상황을 직접 변경할 수 있다. 사용자가 뜬공·스쿱·강도 별도 관찰 포함을 승인했다. 각 구의 포구는 완벽3/블로킹2/터치1/실패0, 송구는 정확신속3/원바운드2/이탈후포구1/악송구0이다. G/F/C는 해당 종류의 유효 포구 평균÷3×10, T_acc는 유효 송구 평균÷3×10. T_pow는 별도 관찰 0~10점의 평균으로 강도와 공 빼는 속도를 감독이 평가한다. 속도 실측 환산 기준은 제공되지 않았으므로 임의 기준을 만들지 않는다. 관찰하지 않은 F/C/강도를 다른 변수로 추정하지 않는다. 정밀 모드는 5변수를 직접 입력한다. 처음 전환 시 현재 관찰 환산값을 편집 시작값으로 보여주되 5구 원본도 보존한다. 모드별 값은 혼합하지 않는다.

배치에는 가장 최근 날짜의 유효 펑고 기록과 새6단계 타격의 전체 유효 회차 평균을 사용한다. 타격 B=(원점수 평균+1)÷6×10, 기능평가100점=B×10이다. 이전1~10점 자료를 새 B로 임의 혼합하지 않는다. 진행 중 타격도 잠정 평균으로 반영하므로 감독 검토가 필요하다. 펑고 기록이 없거나 필요한 변수 미측정 시 해당 포지션은 배정 대상에서 제외한다.

### 제공된 공식

각 식은 기본100점 + 희망1지망5/2지망3 − 감점이다. 음수와105점도 그대로 보존하며 0~100으로 잘라내지 않는다.

- SS/3B: G×3.5 + T_pow×3.5 + T_acc×3.0. G<7 또는 T_acc<7일 때30감점(한 번).
- 1B: C×6 + G×2.5 + F×1.5. C<8일 때30감점.
- 2B: G×4.5 + T_acc×3.5 + F + T_pow.
- CF/LF/RCF: F×5 + T_pow×2.5 + G×1.5 + T_acc. F<6일 때20감점.
- RF: F×3.5 + G×2.5 + T_acc×2 + B×2.
- 포수: C×4 + G×2 + T_acc×1.5 + B×2.5.
- P: 사용자 선택대로 기존 TYPE1 v2.0의9능력 가중 점수를 기본점수로 그대로 사용하고, 다른 자리와 동일하게 희망 가산점5/3을 별도로 더한다. 기존 TYPE1 점수 함수와 가중치는 변경하지 않는다.

TYPE1 매핑은 CF→제1중견수(CF1), RCF→제2중견수(CF2), 포수→본루수(HP)이다. 새 C는 스쿱이며 기존9능력 C(송구 포구)와 다르다. 새 B는 타격이며 기존9능력 B(베이스 처리)와 다르다.

실행 순서: 1B → SS → 3B → CF1 → LF → CF2 → 2B → RF → HP → P. 매 단계 남은 측정 후보의 최고 점수를 배정한다. SS/3B 중 높은 적합도가80 이상인 상위2명은 1B에서 제외하고 SS/3B에 우선 배정한다(내야 두 자리 수에 맞춘 해석). 동점은 고유 ID 순으로 재현하며 실력 우열로 설명하지 않는다. 이는 전체 합을 최대화하는 기존 알고리즘과 별도이다.

새 Selection.method=waterfall, waterfall.version=fungo-waterfall-v1과 후보 ID·당시 기본점수/가산/감점/설명 스냅샷을 저장한다. 피드백은 당시 후보의 실제 C 순위·희망·관찰값을 근거로 생성한다. 빈자리는 수동 보완하거나 측정 후 다시 추천해야 한다. 10명/10포지션/중복 없음/최신 리비전/감독 승인 조건과 승인안 경기 불러오기를 유지한다. 수동 편집 시 기존 TYPE1 수동 점수로 새 배치안이 생성되고 재승인이 필요하다. 최종 종합 타격·수비·주루·팀워크 가중 알고리즘은 계속 TODO이며 이 배치안을 최종 종합 엔트리 점수로 부르지 않는다.
