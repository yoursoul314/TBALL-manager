# BETA 0.7 공통 학생 명단 및 관리 개선

## 최종 동작

- 등록: 선수 & 팀 → 선수 등록 → 이름과 선택 정보·사진 → 저장. 팀이 없어도 등록 가능하며 새 선수의 teamId는 null이다.
- 편성: 새 경기 → 두 운영 팀 선택 → 각 팀의 등록 선수 불러오기 → 선발 10명·후보·미출전·결석 등 지정 → 타순·수비 배치 → 감독 확인 → 경기 생성. 불러오기는 명단 조회이며 전체 학생을 자동 배정하지 않는다.
- 상대 팀에 편성한 학생은 이 팀 후보에서 제외한다. 미편성 · 팀 배정 해제로 반대편 팀에 옮길 수 있다. 경기 엔트리에는 해당 경기 팀 ID를 복사하며 선수 원본의 과거 teamId는 수정하지 않는다.
- 기존 팀 소속은 이전 소속으로 참고 표시한다. 과거 경기 스냅샷·원본 이벤트·정정 이력·사진·평가는 유지한다. 신규 선수 프로필은 공통 명단으로 표시한다.
- 선수 삭제는 archivedAt과 archiveHistory를 추가하는 논리적 삭제다. 등록/삭제된 선수 탭에서 복원할 수 있다. 신규 경기·추천·기능평가 선택에서는 제외하며 과거 기록과 사진은 남긴다. 플레이 진행 중 해당 선수를 삭제할 수 없다.
- 기능평가는 현재 등록된 선수 목록을 사용한다. 출전 불가 학생도 등록 상태라면 평가 가능하다. 전체 초기화 후 예시 학생을 다시 만들지 않으며 직접 등록한 학생만 표시한다. 최초 설치의 가상 예시 명단은 명시적으로 삭제/초기화하기 전까지 등록 명단이다.

## 초기화와 데이터 계약

| 범위        | 지우는 데이터                       | 유지하는 데이터                             |
| ----------- | ----------------------------------- | ------------------------------------------- |
| 경기만      | 경기·이벤트·경기에 연결된 팀워크    | 선수·팀·사진·기능평가·독립 팀워크           |
| 평가만      | 기능평가·회차·감사 이력·팀워크·추천 | 선수·팀·사진·경기·이벤트                    |
| 전체 기록   | 위 두 종류 기록                     | 선수·팀·사진·설정                           |
| 전체 초기화 | 기록·선수·팀·사진·구버전 저장본     | 새 빈 작업공간, 기본 설정, 초기화 시각/범위 |

초기화 준비 → 백업 다운로드 → 저장 확인 체크 → 정확한 확인 문구 → 실행 순서다. 전체 초기화는 10자 이상 암호의 사진 포함 암호화 백업을 요구한다. 일반 기록 초기화는 JSON 백업이다. 백업 후 데이터 리비전이 달라지면 다시 준비해야 하며 진행 중 플레이는 초기화를 차단한다.

스키마7은 선수의 nullable teamId·삭제 이력·lastReset 메타데이터와 빈 경기 목록을 지원한다. 일반 이전은 v1~v6 원문 및 저장 키를 남긴 채 검증 후 v7에 저장한다. JSON은1~7을 읽고7로 내보낸다. 기존 점수와 이벤트를 재작성하지 않는다. 명시적 전체 초기화만 이전 키와 원문 출처까지 제거한다.

전체 초기화의 일반 저장 오류 시 이전 사진·키·원문으로 복구한다. localStorage와 IndexedDB 간 프로세스 강제 종료까지 보장하는 단일 트랜잭션은 없으므로 외부 백업이 필요하다. 서버 인증/접근 권한/멀티기기 동기화와 동시 쓰기 원자적 잠금은 TODO다.

## UI와 조작 단계

| 작업           | 이전                     | 변경 후                                                      |
| -------------- | ------------------------ | ------------------------------------------------------------ |
| 학생 등록      | 팀 드롭다운 선택 후 저장 | 팀 선택 없이 저장: 팀 선택 1회 및 옵션 선택 1회 생략         |
| 경기별 팀 배정 | 기존 소속 명단에서 선택  | 팀별 불러오기 1회 + 학생별 선발 선택 1회; 감독이 경기별 배정 |
| 선수 삭제/복원 | 삭제 없음                | 카드 삭제 → 확인(2회), 삭제된 선수 탭 → 복원                 |
| 기록 초기화    | 없음                     | 범위·백업·확인 후 선택 실행                                  |
| 버전 확인      | BETA 문자열              | BETA 버튼 또는 설정 업데이트 확인 1회                        |

정확한 총 터치 수는 입력 인원과 필드 선택에 따라 달라진다. 팀/선수 주요 관리 버튼은48px 이상이다. 입력칸 최소 너비와 줄바꿈, 12×16px 간격, 날짜/시간 필드의 Safari 너비를 보완했다. 1024/1180 가로,820 세로,390 작은 화면에서 등록/경기/설정 필드의 겹침과 가로 넘침을 검사한다. 닫힌 details의 숨겨진 컨트롤은 제외하고 펼친 상태도 별도 검사한다.

## 업데이트

version.json을 네트워크로 확인하고 서비스 워커를 갱신한다. 새 워커는 활성화하되 현재 화면을 자동 새로고침하지 않는다. 저장하지 않은 경기/평가 초안이 있으면 새 버전 적용을 막는다. 구버전 BETA0.5 화면은 기록 저장 후 앱의 모든 창을 닫고 다시 열어0.7을 확인한다. 브라우저 데이터 삭제는 필요하지 않다.
