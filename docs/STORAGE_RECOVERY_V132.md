# BETA 0.13.2 — 원본 보관 후 저장 공간 복구

## 원인과 변경 범위

0.13.1은 기존 원문을 무손실 압축하지만 localStorage 여유 공간이 거의 없으면 새 키를 쓸 수 없다. Safari 웹사이트 데이터 총량과 localStorage 한도는 서로 다른 값이다. 다른 사이트 데이터 삭제를 복구 방법으로 요구하지 않는다.

경기 규칙·TYPE1 v2.0·평가 점수·척도·사진 저장 방식은 변경하지 않는다. schema12와 JSON 백업1~12 호환성을 유지한다. 일반 로드/저장은 여전히 단일 키 원자적 쓰기이며, 이 복구 절차는 오류 화면의 명시적 버튼으로만 시작한다.

## 복구 순서와 보존 계약

1. 기존 v1~v12를 읽고 기존 스키마·참조·이벤트·평가 감사 검증을 통과한 Workspace를 만든다. 평가 척도 오류나 서로 충돌하는 구버전 탭 기록은 공간 복구로 덮지 않는다.
2. 모든 원문 문자열과 복구할 압축 저장본을 기기 IndexedDB의 tb-manager-recovery-v1 / snapshots에 별도 보관한다. 네트워크로 보내지 않는다.
3. 트랜잭션 complete를 기다린 뒤 별도 읽기로 원문 전체를 대조한다. 원문이 다른 탭에서 바뀌었으면 중단한다.
4. 가장 최신 원본 키를 작은 복구 표식으로 원자적으로 교체한다. 이 표식은 보관본 ID를 가리키며, 앱은 표식이 있으면 예시 데이터 생성·일반 저장을 차단한다.
5. 이미 보관·검증된 티볼의 이전 키만 제거하고, 검증된 압축 v12를 쓰고 다시 읽어 확인한다. 다른 앱 키 및 사진 IndexedDB는 건드리지 않는다. 원본은 보관소에 남는다.
6. 이전 키의 표식은 새 저장본 검증 후 제거한다. 중단된 경우 다음 실행에서 같은 보관본으로 이어서 처리한다. 저장된 새 값이 원본/표식/기대 대상과 다르면 충돌로 중단한다.

복구한 Workspace에는 기존 migrationSource.raw와 감사 이력이 그대로 남는다. 별도 원본 ID는 저장 메타데이터로 유지하며 일반 평가 JSON과 혼합하지 않는다. 복구 완료 시 revision을 올려 과거 탭의 저장을 차단한다. 지원 브라우저에서는 Web Locks로 복구/보관본 정리를 직렬화한다. 일반 저장의 완전한 다중 탭 트랜잭션 잠금은 기존 TODO이며 복구 전 다른 TB Manager 탭을 닫도록 안내한다.

## 아이패드 사용 순서

- 오류 화면에서 앱 업데이트 확인 → 새 버전 적용 또는 새로고침. 상세 오류에 BETA 0.13.2 확인.
- 가능한 경우 원본 복구 파일 다운로드로 외부 파일 백업도 보관한다.
- 다른 TB Manager 탭을 닫고 원본 보관 후 저장 공간 복구를 누른다. 진행 중 앱을 닫지 않는다.
- 완료 후 복구된 기록 열기를 누른다. 기존 선수·평가 횟수를 확인하고 규칙 & 설정에서 일반 JSON 또는 사진 포함 암호화 백업을 보관한다.
- 중단되었으면 중단된 복구 이어하기를 누른다. 오류가 반복되면 보관 원본 포함 백업을 보관하고 상세 오류를 확인한다. 앱 삭제/사이트 데이터 초기화를 하지 않는다.

## 백업·명시적 삭제

검증된 기록 JSON 백업은 기존 가져오기로 복원할 수 있다. 보관 원본 포함 백업은 v1~v12 현 저장값과 별도 보관본 원문을 포함하는 개발자 복구용 파일이다. 사진은 별도 사진 포함 암호화 백업을 사용한다. 이 원문 백업은 암호화되지 않으므로 공개 저장소·공유 샘플에 올리지 않는다.

사용자가 백업·확인을 거쳐 전체 초기화 또는 완전삭제를 실행한 경우에는 원본 보관소도 정리한다. 표식 쓰기 전 실패하여 연결되지 않은 보관본도 포함한다. 정리 완료 전 내구성 있는 정리 대기 플래그를 유지하고 다음 실행에서 재시도한다. 기록만 초기화는 기존 선수·팀·사진과 원문 보존 계약을 유지한다.

## 검증과 한계

- 순수 저장 회귀: 공간0, 보관 실패/재읽기 불일치, 탭 충돌, 현재 저장 실패/표식 제거 실패 후 재개, 보관본 누락, 기존 v12, 백업/이력/점수 보존, 명시적 삭제와 정리 재시도.
- scripts/storage-archive-qa.cjs: 사용자 브라우저와 분리한 WebKit/Chromium에서 실제 localStorage 한도를 채운 가상 자료로 원본 보관/복구/중단/새로고침/사진/추가 저장/백업/전체 초기화를 검증한다.
- scripts/storage-quota-qa.cjs: 기존 압축 이전 및 읽기 전용 복구 화면 회귀를 유지한다.
- IndexedDB까지 용량 부족 또는 사용 불가이면 복구를 완료할 수 없다. 보관 commit/재읽기 전에는 localStorage를 정리하지 않으며, 이후 실패는 표식과 보관본으로 재개한다. OS 강제 종료·브라우저 데이터 삭제까지 보장하는 외부 백업은 아니다.
- 실제 iPad의 기존 데이터 확인은 사용자가 최종 확인해야 한다. 자동 QA는 iPadOS 하드웨어 테스트를 대체하지 않는다.
