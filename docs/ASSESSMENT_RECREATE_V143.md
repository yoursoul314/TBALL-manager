# BETA 0.14.3 · 삭제한 날짜에서 새 평가 시작

삭제된 날짜의 공통 설정이 남아 신규 생성까지 막던 오류를 수정한다. 타격 상세평가·수비 체크리스트·펑고에서 **새 평가 날짜**를 선택하고 삭제했던 날짜를 입력하면 복원 없이 새 평가를 시작한다.

## 보존·마이그레이션

- 내부 schema13 → 14. localStorage 키 tb-manager.workspace.v12는 유지하며 다른 기기의 실제 데이터에는 접근하지 않는다. 이전 원문은 migrationSource에 보존하고 기존 무손실 압축·원본 보관 복구 흐름을 유지한다.
- JSON 백업 1~14 입력, 14 출력. 이전 앱은 새 스키마를 거부한다. 알 수 없는 스키마를 강제 변환하지 않는다.
- dayHistory.restart에 이전 공통 설정, 종류, 이전 기록 ID 목록을 보존한다. 날짜를 새로 열어도 이전 세션·회차·수비 관찰·정정 이력은 삭제 상태를 유지한다. 새 생성은 이전 기록의 복원이 아니다.
- 같은 날짜의 활성 평가가 남아 있으면 신규 생성은 차단한다. 해당 날짜에서 학생 추가·기존 기록 편집을 사용한다. 날짜 전체를 삭제했거나 모든 평가 세션/상황/펑고 기록을 개별 삭제한 경우 새로 생성할 수 있다. 활성 타격 세션에서 회차만 지운 경우 세션은 계속 활성이다.
- 날짜 설정 없는 이전 평가에는 공통 설정을 추가할 수 있다. 기존 기록은 유지한다.
- 생성·이력·설정 교체를 한 번에 검증하고 저장한다. 실패하면 원본과 입력을 유지한다. 브라우저 용량이 실제로 부족한 경우 기존 원본 보관/복구 절차가 필요할 수 있다.

## 기록·화면

- 타격: 새로운 세션 ID와 다음 세션 번호. 학생 목록과 평균은 활성 세션 기준이다.
- 수비: 새로 선택한 학생과 새 목표 횟수로 시작하며 이전 삭제 상황을 횟수/9능력 점수에 포함하지 않는다. 설정 횟수 완료 후 다음 학생 이동을 유지한다.
- 펑고: 취소된 과거 기록과 새 기록을 서로 다른 ID로 보관한다. 같은 학생·날짜의 활성 펑고는 하나이며 이전 기록 복원 시 활성 중복을 차단한다. 기존 학생 변경 화면은 활성 날짜 편집으로 유지한다.
- 이전 삭제 기록은 평가자·기록 관리에서 확인·개별 복원할 수 있다. 새 날짜를 다시 삭제·복원해도 이전 세대의 취소 기록은 함께 되살리지 않는다.
- 선수 완전삭제는 보존된 날짜 설정의 학생 ID도 정리한다.
