# BETA 0.16.0 · 수업 출석·빠른 경기 기록·학생용 엔트리 인쇄

## 사용 순서

1. **수업 출석부**에서 날짜와 학년·반을 선택해 전체 명단을 만든다. 여러 학급을 같은 날짜에 추가할 수 있다. 신규 학생은 명단 갱신으로 추가하며 기존 출석을 바꾸지 않는다.
2. 학생별 출석/결석/지각/조퇴/활동 제한을 터치한다. `미확인 학생 모두 출석`은 이미 체크한 결석 등을 덮어쓰지 않는다. 변경 즉시 저장하며 정정 전후 상태와 시각을 보존한다.
3. **새 경기**에서 해당 날짜의 수업 학급을 선택한다. 출석·지각 중 출전 가능 학생이 선발 또는 교체 후보에 모두 포함돼야 생성할 수 있다. 미확인, 편성 누락, 결석·제한 학생의 출전이 있으면 차단한다.
4. **출석 기준 적용 · 누락 학생 모두 편성**은 출석 대상인 기존 선발·타순·수비를 유지하면서 빈 선발 자리를 채우고 나머지를 교체 후보로 나눈다. 결석·제한 학생은 출전에서 제외한다. 제외된 주장은 직접 변경/해제해야 한다. 양 팀 선발 10명 규칙은 유지한다.
5. 기존 직접/단순 랜덤/실력 균형/희망 포지션 구성도 계속 사용할 수 있다. 랜덤 화면에서 `수업 출석 학생 전체 선택`을 제공한다. 구성 뒤 누락 판정을 다시 수행한다.
6. 경기 목록 또는 기록실의 **엔트리 인쇄**에서 시작 당시 또는 현재 타순·수비를 선택하고 프린트/PDF 저장한다. 학생용 양식은 팀·주장·타순·등번호·수비·후보만 출력한다. 평가 점수·출석 사유는 제외한다.

## 경기 기록 단축

| 상황                   | 이전                                           | 변경 후                                                       |
| ---------------------- | ---------------------------------------------- | ------------------------------------------------------------- |
| 무주자 안타            | 결과 → 개별 확인 → 타임 체크 → 확정 (4터치)    | 결과 → 전체 결과 확인 → 심판 타임·확정 (3터치)                |
| 만루 결과, 주자 4명    | 결과+개별 확인 4회+타임+확정 (7터치, RBI 별도) | 결과+전체 확인+타임·확정 (3터치, RBI 별도)                    |
| 땅볼/뜬공/2루→1루 병살 | 아웃 종류·위치 등을 각각 지정                  | 빠른 결과 버튼으로 미확정 제안, 실제 결과 확인 후 확정        |
| 6-3 수비 연결          | 수비수·행동·목표·주자 등을 반복 선택           | 땅볼 연결 → 포구 수비수 → 1루 아웃 수비수 → 연결 적용 (4터치) |
| 타구 상세 보완         | 기록 수정 화면 탐색                            | 직전 타구 상세 보완, 다음 타자 입력 중에도 가능               |

자동 제안은 사실로 확정하지 않는다. 주자 충돌·누락·아웃 사유·실제 베이스·타점 판정은 검증한다. 마지막 버튼은 **심판이 타임을 선언했음을 확인하고 END_PLAY를 저장하는 단일 동작**이다. 자동 타임이나 임의의 플레이 종료는 없다.

빠른 수비 연결은 실제 `state.defense`의 수비수를 기록원이 선택하고 전체 성공 동작을 확인한 경우에만 생성한다. 땅볼·송구·받기·포스아웃(베이스 처리 관찰 포함)과 자살·보살을 각각 기록한다. 같은 베이스 처리를 두 번 생성하지 않는다. 실패/실책/태그아웃/안전진루/오버런 등은 기존 개별 입력으로 보완한다. 다른 능력이나 미관찰 수비를 자동 성공 처리하지 않는다. 자동 연결된 세부 이벤트는 요약으로 접고 펼쳐 확인한다.

직전 타구 상세 보완은 방향/거리/유형/강도만 REVISE_PLAY로 추가한다. 원본 END_PLAY·수정자·사유·시각을 보존하고 전체 경기를 재생한다. 다음 타자 입력은 START_PLAY ID를 키로 유지한다. 결과/주자/득점 변경은 볼 데드의 전체 수정 화면에서 수행하며 후속 규칙 충돌 시 저장을 거절한다.

## 데이터 이전 계획과 구현

- schema16에 `classDays`를 추가한다. `ClassDay`는 날짜별 학급 목록, 학생 ID/이름/학급/등번호/학급 번호 스냅샷, 상태, 생성·수정 시각, 상태 변경 이력을 가진다. 같은 날짜 중복 출석부/학생/학급/이력 ID와 잘못된 참조는 검증한다.
- 새 경기에는 선택한 학급의 `Game.entry.attendance` 스냅샷을 저장한다. 이후 출석 수정이나 학생 소속 변경으로 과거 경기 편성을 다시 만들지 않는다. 후보 편성은 실제 출전이나 경기력 0점으로 계산하지 않는다.
- v15 → v16은 기존 모든 데이터에 빈 `classDays`만 추가한다. 과거 경기 출석을 추정하거나 학생을 자동 출석으로 만들지 않는다. 원본/평가/이벤트/사진 ID 연결을 보존하며 migrationSource에 전체 데이터를 다시 중첩하지 않는다.
- 저장 키는 기존 `tb-manager.workspace.v12`를 유지한다. 검증 후 기존 원자적 저장/압축/용량 오류 복구 경로를 사용한다. 실패 시 이전 원본을 유지한다. JSON v1~v16 읽기, v16 쓰기. 최신 백업은 구버전 앱에서 지원하지 않는다.
- 사진 IndexedDB는 변경하지 않는다. 모든 기록/전체 초기화는 출석부도 비우며 경기만/평가만 초기화는 출석부를 보존한다. 선수 완전삭제의 기존 확인 절차 안에서 연결 출석·이력·경기 스냅샷도 정리한다.
- 경기 기록지 인쇄 버튼·종이 입력 안내·공개 빈 기록지 HTML/생성 스크립트는 제거한다. 이전 기록과 내부 과거 양식 회귀 테스트는 보존한다. 신규 엔트리 인쇄는 데이터를 쓰지 않는다.

## 검증과 남은 범위

출석 생성·정정·누락 차단·후보 포함 전원 편성·백업 왕복·v15 보존, 빠른 땅볼/병살 자살·보살·RULE02, 현재 초안 유지 중 과거 타구 수정, RBI 판정, 저장 실패/중복 방지, 학생용 출력·현재/초기 편성·공통 CSS 간섭을 자동 검증한다. RULE01~08 및 TYPE1 v2.0 파일은 바꾸지 않는다. 실행 결과와 화면 검증은 `VALIDATION.md`에 기록한다.

출석은 기기 로컬 기록이며 서버 동기화·교사 인증은 미구현/보류다. 여러 교시의 동일 학급 출석을 별개 세션으로 관리하는 기능, 전체 출석 CSV, 실제 출전 시간을 기준으로 교체를 자동 강제하는 기능은 이번 범위에 없다. 실제 iPad Safari 키보드/AirPrint/PDF 저장은 기기에서 추가 확인이 필요하다. 매우 긴 팀명·많은 교체 후보는 다음 페이지로 이어질 수 있으며 자르지 않는다.
