# BETA 0.14.4 — 경기 기록지 인쇄 · 타점 · 평가 복원 검증

## 사용 순서

1. 경기 기록실에서 새 경기를 만들고 날짜·엔트리·타순·수비 배치를 확정한다.
2. 경기 목록 또는 상세 화면의 **기록지 인쇄**를 누른다.
3. **빈 기록지 · 타순 포함** 또는 **현재 기록 포함**을 선택한다. 빈 상세 기록지는 1/2/3/5/10/20장 중 선택하며 1장당 6타석이다.
4. **프린트 / PDF 저장**에서 A4 가로, 배율 100%, 브라우저 머리글/바닥글 끄기를 권장한다. 실제 출력은 기기의 인쇄 설정을 따른다. **인쇄 양식 HTML 저장**은 외부 파일·스크립트 없이 열 수 있는 문서를 만든다.
5. 종이의 타석별 No.를 팀별 기록지와 상세 기록지에 같이 적는다. 득점 주자, 타점 인정 여부, 아웃 종류·위치, 수비 관여·실책, 임시주자·정식 교체의 시점을 따로 기록한다.
6. 나중에 같은 경기 ID를 열고 **종이 기록 입력 안내**를 켠다. 현재 이닝·타순/입력 완료 타석과 대조하며 순서대로 기존 입력 화면을 사용한다. 이미 입력한 타석은 **플레이 수정 · 이력**에서 정정한다.
7. 경기별 인쇄 전에도 경기 목록의 **공통 빈 기록지 양식 열기**를 쓸 수 있다. 이 경우 같은 날짜·팀·엔트리로 경기를 만든 후 문서에 경기 ID를 기입한다.

## 양식

- 팀별 타순 × 이닝 기록지: 5이닝·10타순씩 분할, 등번호/시작 수비 배치/교체 후보, 결과·S/F·발생 득점·RBI·상세 순번, 타순 자리 전체 PA/H/RBI 합계와 이닝 득점.
- 플레이 상세 기록지: 타자 포함 모든 주자 결과, 포스/태그 등 아웃과 위치, 타점 인정 주자, 복수 수비수·PO/A/E·실책 추가 진루·심판 타임.
- 교체·특수 판정 기록지 및 전산 등록 순서. 정식 교체와 임시주자를 구분한다.
- 현재 기록 사본은 유효 이벤트를 재생한다. 정정·취소를 반영하고 RULE02로 취소된 득점·타점을 합산하지 않는다. 경기 시작 엔트리를 표의 기준으로 두고 교체 선수는 해당 이닝 칸/변경 별지에 표시한다.
- 공통 양식은 `node scripts/generate-scorebook-template.mjs`로 같은 React 인쇄 컴포넌트에서 생성한다. 공개 파일에는 빈 선수 이름만 있으며 실제 학생 자료·사진은 포함하지 않는다.

## 타점 입력 보완

원인: RBI는 명시적 판정 이벤트가 있어야 집계되는데 간편 화면에서 판정 입력이 숨겨져 있었다. 프로필에도 타점 숫자가 없었다.

득점 주자마다 간편/상세 공통 화면에서 **타점 인정 / 타점 없음**을 선택한다. 선택 전 새 플레이 확정을 막고, 결과·주자 이동을 바꾸면 해당 판정을 다시 확인한다. 인정한 주자별로 기존 `RBI` 상세 이벤트 하나만 저장한다. 실책 득점·FC 등을 일괄 자동 추정하지 않는다. 홈런 타자의 본인 득점도 동일하게 판정한다. RULE02 롤백 시에는 득점·타점 모두 0으로 안내하고 기존 엔진이 반영을 제외한다.

프로필과 플레이 타임라인에 타점을 표시한다. 경기 통계·CSV의 기존 RBI 집계 계약은 그대로다. 과거에 누락된 타점은 원본을 보존하는 `REVISE_PLAY`로 기록원이 확인해 정정한다. 과거 득점을 타점으로 일괄 소급 생성하지 않는다.

## 삭제 → 같은 날짜 새 평가 → 이전 기록 복원

- 타격: 다른 세션 ID로 유지하며 명시적으로 복원한 이전 유효 회차와 새 유효 회차를 각 1회씩 합산한다. 이전 8점 1회 + 새 2점 2회 = 3회 12점, 평균 4점(이전 1~10 척도 기준 40/100). 날짜 평균을 재평균하지 않는다. 취소 회차·취소 세션은 제외한다.
- 수비 체크리스트: 새 목표 횟수 초과 복원은 실패하며 원본을 변경하지 않는다. 목표를 늘려 복원하면 각 관찰을 1회씩 반영한다.
- 펑고: 같은 학생·날짜에는 활성 기록 1개만 허용한다. 새 기록이 활성 상태인 동안 이전 기록 복원은 명확한 오류로 차단한다. 새 기록을 삭제한 후 이전 것을 복원하면 입력창·학생 비교표·추천 점수가 이전 점수로 함께 바뀐다. 두 점수를 임의로 섞거나 합산하지 않는다.
- 반복 복원, JSON 백업/복원, 원본 회차·수정 이력 보존을 회귀 검증한다. 평가 계산식/운영 정책은 변경하지 않는다.

## 데이터 보존

스키마는 **14**, 저장 키는 **tb-manager.workspace.v12**로 유지한다. 새 저장 모델이나 마이그레이션이 필요하지 않다. 인쇄·HTML 내보내기는 읽기 전용이며 사진에 접근하지 않는다. 종이 입력도 기존 START_PLAY → END_PLAY, 판정 검증, 저장 실패 보호, 정정 이력을 사용한다. 실제 학생 데이터로 테스트하지 않는다. RULE01~08·TYPE1 v2.0 파일은 변경하지 않는다.

## 검증 범위와 남은 확인

자동 테스트는 인쇄 진입/브라우저 print 호출, 양식 HTML의 CSS 포함·문자 이스케이프, 이닝 분할, 정정 후 점수 일치, 복수 타점/실책 득점, 평가 복원과 비교표를 검증한다. 최종 실행 결과는 VALIDATION.md에 기록한다.

로컬 브라우저 연결 실패 후 PC 제어 도구가 현재 URL을 안전하게 확인하지 못해 화면 조작이 중단됐다. 이번 변경의 실제 인쇄 미리보기·브라우저 반응형 화면·아이패드 AirPrint/용지별 출력은 아직 확인하지 못했다. 기기에서 한 장 출력해 여백·잘림을 추가 확인해야 한다. 수비 관여가 매우 긴 기록은 다음 페이지로 이어질 수 있다. 종이 사진 OCR/자동 일괄 입력, 프린터 직접 연결은 구현 범위에 포함하지 않는다.

## BETA 0.14.6 · A4 가로 페이지 보완

- 화면의 기록지 내용 폭과 인쇄 내용 폭을 281mm로 통일한다. A4 가로 297×210mm, 상하좌우 8mm 여백으로 실제 내용 높이는 194mm이다. 이전 화면의 추가 4mm 안쪽 여백은 제거한다.
- 빈 타석의 다이아몬드를 절대 위치로 배치해 행 높이에 영향을 주지 않게 한다. 이름·숫자·수비 기록을 잘라내는 `overflow:hidden`, 고정 페이지 높이, 축소 변환은 사용하지 않는다.
- 다음 양식 앞에서만 페이지를 나눈다. 마지막 양식 뒤 강제 넘김은 없다. 표 전체의 분할 금지를 해제하고 긴 표는 자연스럽게 이어지며 머리글은 반복한다. 이닝 득점(tfoot)은 마지막에 한 번 출력한다.
- 기록이 없는 현재 사본은 빈 상세/교체 페이지를 생성하지 않는다. 10이닝·여러 상세 장수와 40개 수비 관찰의 원문 보존을 회귀 검증한다.
- 인쇄 화면에 iPad PDF 저장 순서와 첫 장/마지막 장의 오른쪽 RBI 열·하단 경기 ID 확인 안내를 제공한다. 인쇄와 PDF는 동일 CSS를 사용한다. 저장 결과를 앱이 직접 감지하거나 성공했다고 자동 표시하지 않는다.
- 버전 확인 파일이 0.14.3에 남아 있던 문제도 수정한다. 앱/패키지/잠금 파일/공개 버전 파일 일치 테스트로 반복 업데이트 안내를 예방한다.
- 변경 파일: ScorebookPrint.tsx, scorebook.css, ScorebookPrint.test.tsx, config/version.test.ts, 공개 공통 양식과 버전 파일, 패키지 버전, README/SPEC/VALIDATION/본 문서.
- 저장 스키마와 원본 경기 이벤트는 그대로이며 마이그레이션은 없다. 프린트/HTML 내보내기는 읽기 전용이다.

### 현장 확인 항목

실제 iPad Safari/AirPrint와 PDF 파일 재열기는 이 개발 환경에서 직접 검증되지 않았다. 빈 5이닝 양식은 선공·후공·상세 2장·교체 안내 총 5개 양식이다. 실제 출력 장수는 긴 입력 내용과 용지 설정에 따라 늘 수 있으며, 인쇄 창에서 A4 가로와 모든 페이지를 확인한다. PDF는 해당 인쇄 미리보기에서 공유→파일에 저장한 뒤 파일 앱에서 다시 열어 페이지 나눔을 확인한다. 웹페이지 전체 화면 캡처 PDF는 A4 인쇄 PDF와 다른 방식이다.
