# BETA 0.14 — 평가 기록 삭제·복원 및 평가자 등록

## 사용 방법

- 기능평가 & 팀워크 → 평가자·기록 관리에서 평가자 이름/별칭을 한 번 등록한다. 각 평가 화면의 평가자 등록·관리에서도 등록할 수 있다.
- 타격 날짜/개별 세션, 수비 날짜/개별 기록, 펑고 날짜/개별 기록 및 정정자는 이름 버튼으로 선택한다. 과거 기록의 문자열 평가자는 그대로 보존한다. 사용 중지는 앞으로 선택할 명단을 숨기며 과거 이름을 변경하지 않는다.
- 타격·수비·펑고 날짜 생성 화면에 선택 날짜 삭제 버튼을 제공한다. 개인 타격 세션 설정에도 세션 삭제/복원이 있다.
- 평가자·기록 관리에서 타격 세션/타격 회차/수비 상황/펑고 기록을 선택하고 날짜별 개별 기록 삭제·복원을 수행한다. 날짜 전체 복원도 이곳에서 수행한다.
- 삭제 확인에는 처리 평가자와 터치형 사유가 필요하다. 날짜 전체의 모든 유효 기록이 영향받음을 안내한다. 삭제는 논리적 취소이며 원본과 정정 이력은 유지한다. 개별 기록을 삭제했던 상태는 날짜 전체 복원 시 유지한다.

## 저장 호환성 계획과 구현

먼저 기존 v12 저장·백업·용량 복구 계약을 점검했다. 동일한 tb-manager.workspace.v12 키를 유지하면서 내부 Workspace schema를13으로 확장한다. 키의 v12 접미사는 역사적 이름이며 새 키를 복제하지 않는다. 압축 codec 및 원본 보관소/사진 IndexedDB는 그대로다.

v12 읽기 시 전체 검증 후 v13을 같은 키에 원자적으로 교체한다. v12 원문은 migrationSource(schemaVersion12).raw에 보존하며 기존 원본 보관소 ID와 이전 키 기준본 메타데이터도 유지한다. 저장 실패는 기존 키를 덮지 않으며 읽기 전용 확인과 BETA0.13.2의 원본 보관 복구를 사용할 수 있다. 이전 버전 앱은 schema13을 읽지 못해 보호 화면으로 멈추므로 신규 관리 정보를 조용히 제거하지 않는다. 새 앱에서 저장한 후 구버전으로 돌아가지 않는다.

JSON 백업 읽기1~13, 쓰기13. 이전 평가자 이름을 임의로 신규 명단에 등록하거나 기존 점수/평가 척도/회차를 변환하지 않는다. 복구가 중단된 BETA0.13.2의 schema12 원본 보관본도 이어서 schema13으로 복구한다. 보관본 원문은 불변이다.

신규 assessmentManagement:
- assessors: id, name, createdAt, archivedAt. 공백 제거·중복 이름/ID·길이를 검증한다.
- dayHistory: 날짜, 평가 종류, 삭제/복원 상태, 처리자, 시각, 사유, 영향을 받은 기록 ID와 정정 ID. 작업 이력은 추가만 한다. 개별 삭제는 기존 타격 감사/수비·펑고 revisions를 사용한다.

날짜 삭제는 당시 유효했던 기록만 취소한다. 복원은 이 작업으로 취소한 기록만 복구하며, 이후 변경 충돌은 차단한다. 이미 완전삭제된 학생의 제거된 기록은 다시 만들지 않는다. 삭제 날짜에 새 평가를 추가하려면 날짜부터 복원한다. 수비 개별 복원 시 목표 횟수 초과도 차단한다.

기록/평가 초기화는 평가자 명단을 유지하고 날짜 삭제 이력을 비운다. 전체 초기화는 평가자 명단까지 비운다. 서버 전송은 없고 모든 새 관리 정보는 기기 저장·기존 백업에 포함된다.

## 계산 및 화면

삭제한 세션/회차/수비/펑고는 기존 취소 제외 규칙으로 누적 평균·9능력·펑고 추천 입력값에서 제외된다. 미측정은 계속 null이다. RULE01~08, TYPE1 v2.0, 타격6단계 환산 및 주루40:60은 변경하지 않는다. 경기 이벤트·학생·사진은 평가 삭제의 대상이 아니다.

평가자 버튼은48px 이상, 명단은 줄바꿈한다. 기록 관리 목록은20개 단위로 표시하며 아이패드 가로/세로 및 PC에서 가로 넘침을 점검한다. 저장 실패 시 삭제 확인 화면과 원본, 평가자 등록 입력을 유지한다. 미저장 측정 중 관리 탭/날짜 삭제 이동은 기존 dirty 보호를 적용한다.

## 검증과 남은 사항

순수 함수: 평가자 중복·사용 중지, 빈 날짜 삭제, 타격/수비/펑고 날짜 및 개별 삭제/복원, 이전 취소 제외, 평균·9능력 재계산, 목표 횟수, 백업·현재 키 이전·실패 원문 보존·초기화.
UI: 등록→터치 선택, 날짜/회차 삭제와 복원, 처리자 미선택 차단, 등록/삭제 저장 실패 보존. 기존 전체 회귀와 원본 보관 복구도 재검증한다.
실제 아이패드의 학생 자료는 건드리지 않고 합성 자료만 사용한다. 하드웨어 키보드/접근성 확대 및 실제 사용자 자료의 최종 확인은 기기에서 필요하다. 서버 인증/동기화 및 평가 최종 가중치 TODO는 유지한다.
