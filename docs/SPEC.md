# TB Manager 개발 명세 v0.2

## 목적과 고정 계약

중학교 티볼 수업용 React + TypeScript + Vite PWA. RULE01~08 및 TYPE1 v2.0 가중치는 이전 릴리스의 설정 파일을 그대로 유지한다. 원문과 수치는 [DECISIONS.md](DECISIONS.md)에 있다. 3아웃으로 공수교대하지 않으며, 전원 타격·잔루 승계·마지막 타자 1루 포스아웃 롤백·동일 완료 이닝 승패 원칙은 변하지 않는다.

최종 종합 선발 알고리즘은 TODO다. 현재 추천은 9개 수비 기능 점수로 TYPE1 적합도 합계를 최대화한 시범 배치다. 사용자 승인 전 draft, 명시적 감독 승인 후에도 시범 배치 승인일 뿐 최종 확정 엔트리가 아니다.

## 계층

- components: 화면과 입력. BattedBallMap, PlayForm, PlayDetailsEditor, HistoryEditor, DefenseEditor, TeamworkPanel.
- config/domain: 고정 규칙·가중치, 기록 분류, 타입 계약.
- engine: 순수 이벤트 재생, 상태 전이, 세부 이벤트 교차 검증.
- statistics: 유효 원본 이벤트에서 타격·수비·주루·득점·팀워크 기회 집계.
- evaluation: TYPE1 가중합과 중복 없는 최대 합계 배치. 정책과 경기 규칙을 분리.
- data: Zod 검증, v1 마이그레이션, localStorage 리비전, JSON/CSV.

## 저장 모델과 이전

Workspace.schemaVersion=2. Player, Team, Game, Assessment, Selection, EvaluationPolicy는 기존 구조를 유지한다. GameEvent는 기존 v1 봉투를 보존하며 새 기록은 schemaVersion=2다. ID, gameId, 연속 sequence, deviceId, UTC recordedAt을 유지한다.

상세한 무손실 이전 순서·실패 처리·백업 계약: [MIGRATION.md](MIGRATION.md).
v1 키는 남기고 v2 키에 쓴다. v1 원문은 legacySource.raw에도 보존한다. 기존 팀워크는 legacyTeamwork로 보존한다. 구버전 탭의 v1 후속 변경을 탐지하면 덮어쓰기를 거절한다. 손상·중복 타격 등 충돌은 자동 보정하지 않는다.

JSON 백업: format=tb-manager-backup, version=2, exportedAt, workspace. v1/v2 입력 지원, v2 출력. v2는 구버전 앱에서 읽을 수 없다. 복원 전 10MB 제한, 스키마/참조/전체 경기 재생 검증 및 현재 데이터 백업을 수행한다.

## 타구와 플레이

END_PLAY는 심판 타임 시 한 트랜잭션으로 저장한다. 타자 및 모든 잔루 주자의 최종 위치와 행동, 아웃 사유와 위치를 직접 기록한다. 자동 진루/심판 판정 추정은 하지 않는다.

타구 속성을 분리한다.

| 필드      | 의미                       | 값                                                        |
| --------- | -------------------------- | --------------------------------------------------------- |
| direction | 좌우 방향                  | left / center / right                                     |
| distance  | 거리 구간                  | near / middle / far, 과거 미기록은 null 또는 필드 없음    |
| quality   | 타구 유형 (v1 필드명 유지) | ground / line / fly                                       |
| strength  | 타구 강도                  | strong / normal / weak, 과거 미기록은 null 또는 필드 없음 |

direction×distance = 9구역. 큰 버튼을 갖춘 필드맵에서 선택한다. 거리의 실제 미터 경계는 미확정이므로 현장 관찰 분류이며 실측값처럼 표시하지 않는다. 새 플레이는 구역·강도 선택 후 저장한다. 기존 플레이 편집은 과거 미기록을 그대로 보존할 수 있다.

result는 single/double/triple/home-run/out/error/sacrifice-fly/fielders-choice. FC는 타수에 포함하고 안타가 아니다. 희생플라이 타수 처리만 기존 TODO 정책을 따른다.

### 별도 세부 이벤트

END_PLAY.details는 ID가 있는 판정/관찰 이벤트 배열이다. 전부 원자적으로 저장하여 타임 전후의 중간 통계가 저장되지 않도록 한다. 경기 상위 봉투와 별개인 세부 이벤트이며, 각 참조 ID는 해당 플레이 안에서 검증한다.

| type             | 내용                                             | 검증                                                          |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------- |
| FIELDERS_CHOICE  | 아웃을 시도한 기존 주자                          | FC 결과에 정확히 1개, 타자 제외                               |
| RBI              | 타점으로 인정한 득점 주자                        | 해당 플레이 홈 도달, 동일 주자 중복 금지                      |
| DEFENSIVE_ERROR  | 수비수·실책 유형·메모                            | 상대 팀 명단, 유효 유형                                       |
| ERROR_ADVANCE    | 주자·실책 전/후 베이스·원인 errorId              | 실책 링크, 순방향·최종 위치 및 안타 루타와 일치               |
| FIELDING_ACTION  | 선수·포지션·포구/송구/베이스/아웃 기여·성공 여부 | 아웃 기여 대상 검증, 성공이면 실제 아웃                       |
| DEFENSIVE_CREDIT | 수비수·자살 PO 또는 보살 A·아웃된 주자           | 실제 아웃, 한 아웃 PO 중복 금지, 동일 수비수/아웃 A 중복 금지 |

실책 유형: 땅볼 처리, 뜬공 낙구, 송구 포구, 송구 방향, 송구 거리·강도, 베이스 처리, 상황 판단, 기타.

END_PLAY.fielding은 기존 9능력 관찰 배열이다. 같은 플레이에서 여러 선수·능력·기회를 입력할 수 있다. 실패 관찰을 실책으로, 성공 관찰을 자살/보살로 자동 변환하지 않는다. 미기록 공식 기여를 추정하지 않는다.

RBI는 기록원의 명시적 판정이다. 일반 야구의 세부 타점 예외를 임의 도입하지 않는다. 자동 판정/학교별 채점 기준은 TODO. 안타 후 실책 진루는 H/TB를 늘리지 않고 errorAdvanceBases로 별도 집계한다. RULE02 롤백 시 RBI·실책 진루도 해당 플레이의 득점/진루 통계에서 제외하고 실제 수비 관찰·기여는 보존한다.

## 상태 전이와 중복 타격 방지

PITCH/START_PLAY/END_PLAY/TEMP_RUNNER/SUBSTITUTE/DEFENSE/RUNNER_VIOLATION/FINISH_GAME/RETRACT는 기존 규칙을 유지한다.

GameState.batted는 현재 공격 이닝에 타격을 완료한 학생 ID를 추적한다. 타석 완료·PITCH·START_PLAY에서 재타격을 차단한다. 공격 중 이미 타격한 학생을 아직 타격하지 않은 슬롯으로 교체하는 입력도 차단한다. 이미 타격한 자리의 교체, 다음 공격 이닝의 재출전, 수비 측의 교체는 가능하며 횟수 제한을 추가하지 않는다.

DEFENSE 전용 화면은 볼 데드에서 출전 타순 선수들의 TYPE1 위치를 변경한다. 선수를 중복 배치할 수 없다. 정식 교체 및 임시주자와 별도이며 타순을 변경하지 않는다.

공통 완료 이닝 min(away,home)만 승패에 사용한다. 전체 기록 통계와 선발용 통계(미완료 이닝 포함/제외 TODO 정책)는 분리한다.

## 과거 플레이 정정과 감사

REVISE_PLAY = targetId(원본 END_PLAY ID), replacement(새 END_PLAY payload), reason, author. 시각·작성 기기는 이벤트 봉투에 남는다. 수정된 원본을 다시 수정할 때도 원본 ID를 대상으로 한다.

effectiveEvents는 원본을 변형하지 않고 수정 결과만 재생 투영에 적용한다. 원본·모든 수정은 백업에 남는다. 수정 사유/작성자 필수, 없는 대상·취소된 대상 거절. 전체 이벤트를 재생하여 모든 후속 주자, 타순, 점수를 검증하고 충돌하면 원본/저장을 그대로 유지한다. 통계의 기존 합계를 부분 변경하지 않는다.

화면은 볼 데드에서 타구 플레이를 수정한다. 수정 전 원문과 이전 수정 이력을 확인할 수 있다. 삼진의 과거 투구 재작성과 여러 플레이 일괄 정정은 TODO다. RETRACT는 기존과 같이 최근 유효 경기 이벤트를 취소하며 원문을 남긴다.

## 팀워크 5영역

의사소통25·커버백업25·역할수행20·동료지원15·공동전술15 가중치를 고정한다.

새 관찰은 category, opportunity(offered/not-offered), outcome(performed/partial/not-performed/unobserved), 행동 메모, 관찰자 별칭, 시각, 선택 경기로 구성한다. 기회 없음이면 결과는 미관찰이어야 한다. 기회 수와 실제 관찰 결과를 각각 집계한다. 기회 없음·미관찰은 미수행으로 계산하지 않는다. 부분 수행의 점수 환산과 종합 선발 반영은 TODO다.

모든 v1 기록은 원래 분류·1~5 점수로 legacyTeamwork에 보존하고 화면에서 확인한다. 책임감/존중을 새 영역으로 자동 매핑하거나 새 점수에 합산하지 않는다.

## 통계와 내보내기

타석·타수·안타·루타·삼진·득점·RBI·FC, PO/A/E, 수비 능력 관찰 성공/시도, 수비 동작 분포, 실책 유형, 실책 진루 베이스, 주루 아웃/위반을 재계산한다. 9구역·타구 유형·강도는 독립 분포다. 기존 방향만 있는 기록은 방향 분포에 남고 9구역의 임의 칸에 배치하지 않는다. CSV에는 정책 버전·범위·미확정 여부와 새 지표를 포함하며 수식 주입을 이스케이프한다.

## 개인정보·운영 제한

실제 학생 개인정보를 저장소/배포 샘플/테스트에 포함하지 않는다. 가상 샘플만 사용한다. 모든 화면에서 서버 인증/접근 권한 미구현 및 실명·학번 입력 금지를 알린다. 이름 입력은 별칭으로 사용한다.

localStorage는 암호화 보관이나 서버 인증이 아니다. 동시에 여러 기기에서 실전 기록하지 않는다. IndexedDB 트랜잭션·교사 인증·학급별 ACL·경기 기록자 lease·서버 CAS·암호화 백업·보존기간·승인 권한은 TODO다. 사용자 승인 입력은 현재 로컬 기록일 뿐 인증된 전자서명이 아니다.

`?preview=1`은 QA/가상 체험용이며 sessionStorage를 사용하여 실제 브라우저 저장소와 분리한다. 화면에서 검증 모드임을 표시한다.
