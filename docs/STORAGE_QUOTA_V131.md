# BETA 0.13.1 — 저장 공간 초과 복구

## 원인과 보존 계획
아이패드 Safari 화면의 The quota has been exceeded 오류는 localStorage 쓰기 실패다. 평가 척도 불일치가 아니다. 기존 저장 방식은 migrationSource.raw와 각 _vNBaseline에 이전 전체 문자열을 중복 포함하므로 여러 번 업데이트한 기기에서 중첩 사본이 커진다.

기존 키를 지워 공간을 확보하지 않는다. schema12, 선수·경기·평가 원본과 감사 이력, migrationSource 및 구버전 변경 감지 기준을 유지한다. 사진 IndexedDB는 접근하거나 변경하지 않는다. 원본의 저장 표현만 무손실 압축한다.

## 구현
- src/data/storageCodec.ts: 128,000자 이상 JSON은 lz-string 1.5.0 UTF16 압축 봉투(format/encoding/length/checksum/payload)로 저장한다. 압축 전후 문자열 일치를 검사하고 원본보다 작을 때만 채택한다. 작은 기록의 quota 오류도 압축 재시도한다. 단일 setItem 성공 이후에만 저장 성공을 반환한다.
- 압축하지 않은 기존 v12와 새 압축 v12를 모두 읽는다. 길이·체크섬 오류는 원본을 보존하고 중단한다. 압축은 암호화가 아니다. 전체 데이터 스키마나 평가 계산은 바뀌지 않았다.
- LocalWorkspaceRepository.load(false)는 검증만 수행하고 저장하지 않는다. 저장 공간이 전혀 없어도 검증된 기존 기록의 건수 확인 및 일반 JSON 백업을 제공한다. 손상·구버전 충돌을 무시하거나 이전 키로 조용히 되돌리지 않는다.
- 오류 화면: 용량 부족 설명, 원본 복구 파일, 쓰기 없는 기존 기록 확인·JSON 백업, 앱 버전·업데이트·다시 열기. 사진은 별도 저장소에 남아 있음을 안내한다.
- 외부 JSON 백업은 기존의 읽을 수 있는 형식을 유지한다. 중첩 원문을 포함한 큰 백업의 재복원 한도를 10MB에서 64MB로 늘린다. 버전1~12 백업과 사진 포함 암호화 백업을 유지한다.

## 검증
- npm run check: 52파일 265테스트, 타입 검사와 빌드 통과.
- 추가8테스트: 중첩 v8~v11 원문 보존, 압축 이전·저장·재로드·백업 왕복, 리비전/구버전 충돌 보호, 용량0 쓰기 없는 확인, 한글/이모지/이스케이프 보존, 압축 손상 차단, 오류 화면 동작.
- scripts/storage-quota-qa.cjs: 격리된 가상 자료로 실제 브라우저 localStorage 한도를 채워 이전 쓰기 실패를 확인한 뒤 새 방식의 이전/추가 저장/재로드를 검사한다. 용량0 화면과 백업 안내도 검사한다. 실사용 기기의 저장소를 읽거나 변경하지 않는다.
- RULE01~08와 TYPE1 v2.0 파일 해시 불변. 실제 iPad 원본을 받지 않았으므로 해당 기기의 복구 완료 여부는 업데이트 후 확인이 필요하다.

## 한계·다음 단계
- 압축 후에도 기기의 전체 저장 공간이 부족하면 자동 삭제하지 않고 백업 화면에 머문다.
- 원본 아카이브를 IndexedDB에 중복 없이 옮기는 장기 구조는 별도 단계다. 이 수정은 기존 데이터와 동기 저장 계약을 유지하면서 용량 급증을 줄인다.
- 서버 전송·개인정보 수집을 추가하지 않았다. GitHub에는 코드와 가상 검증만 포함한다.

## 브라우저 결과
