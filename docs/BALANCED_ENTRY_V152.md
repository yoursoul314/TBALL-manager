# BETA 0.15.2 · 균형 구성과 주장 고정

## 사용 순서

1. 새 경기에서 선공·후공 팀을 정한 뒤 랜덤 구성을 누른다.
2. 필요하면 선공·후공 주장을 먼저 선택한다. 출전 가능한 서로 다른 학생만 지정한다. 주장은 참가 학생 목록에서 제외되며, 각 팀 선발 10명에는 포함된다.
3. 나머지 참가 학생을 학년·반·검색으로 선택한다. 주장 포함 총 20명 이상이어야 한다.
4. 단순 랜덤 또는 실력 균형을 적용한다. 균형에서는 수비 출처를 9능력 평균 / 최근 유효 펑고 5항목 평균 중 선택한다.
5. 팀별 선발·후보·측정 인원·타격/수비 평균 차이를 확인한다. 타순과 수비 포지션을 직접 조정하고 감독 확인 후 생성한다.

재추첨과 균형 교환은 주장의 팀과 선발 상태를 유지한다. 주장의 타격·수비 점수도 비교에 포함한다. 한 팀만 주장 지정할 수도 있다. 미지정으로 해제하면 추첨 대상으로 다시 선택할 수 있다. 팀을 변경하면 그 팀의 주장 고정 조건을 해제한다. 결석·출전 불가로 변경된 주장은 자동 편성을 차단하므로 고정 조건을 다시 확인한다.

주장 지정은 **이번 새 경기의 자동 구성 조건**이다. 전역 팀의 영구 주장 직책으로 저장하지 않는다. 생성한 경기의 실제 선발·타순·수비는 기존 경기 스냅샷으로 보존한다. 직접 구성에서는 학생을 변경할 수 있고, 이후 다시 자동 구성하면 현재 지정된 주장 조건을 적용한다. 주장 변경만으로 기존 초안을 재편성하지 않고 적용 버튼을 눌러야 한다.

## 빠른 팀 배정 슬롯

직접 구성 → 등록 선수 불러오기 → 학생의 ‘팀 배정 대상 선택’ 체크 → 하단 선공/후공 슬롯 터치. 한 명 또는 여러 명을 한 번에 배정하며 남은 선발 자리를 채운 뒤 초과 인원을 후보로 둔다. 이미 상대 팀에 있던 학생을 이동하면 이전 팀의 상태·타순·수비 배치를 제거한다. 양 팀 중복은 생기지 않는다. 기존 선수의 전역 팀 속성은 변경하지 않는다.

이동으로 선발이 9명이 되면 감독이 보충해야 한다. 후보를 자동 승격하거나 비어 있는 수비에 임의 선수를 넣지 않는다. 선수 수정 후 평균을 다시 표시하며 감독 확인을 해제한다. 원래의 학생별 상태 선택·일괄 상태 지정·승인 배치안 불러오기도 유지한다.

## 평가 자료와 균형 기준

- 타격: 기존 `summarizeBatting().selectedScore`. 규칙 & 설정의 출처를 따른다. 상세 기록은 기존 유효 회차 누적 평균과 6단계 선형 환산을 그대로 사용한다. 상세 미측정일 때 수동 점수를 자동 혼합하지 않는다.
- 수비 9능력: 선수별 기존 평가 출처(수동/체크리스트)를 따르며 9개 항목이 모두 있을 때만 산술평균한다. TYPE1 포지션 적합도 가중치와는 별도의 팀 편성용 비교값이다.
- 펑고: 기존 최신 유효 기록 정책을 따라 5항목이 모두 있는 경우 평균 × 10으로 비교한다. 미관찰 항목을 다른 자료로 채우지 않는다.
- 미측정은 null이고 0점과 다르다. 실제 0점은 유효 점수다. 취소·복원·정정은 기존 계산 함수의 유효 기록 정책을 따른다. 양쪽 모두 해당 지표 자료가 있어야 평균 차이를 표시한다.
- 전체 참가자와 선발 10명 각각에 대해 타격·수비 측정 비율 차이를 먼저 줄이고, 그다음 두 평균 차이의 합을 줄인다. 타격·수비 차이를 같은 중요도로 다루는 **편성용 초안 기준**이며, 공식 종합 선발 배점이나 주루 40:60을 바꾸지 않는다.
- 무작위 시작 3개, 각 최대 16회 선수 쌍 교환. 80명까지 전체 쌍, 초과 시 회당 3,200쌍을 조사해 실행량을 제한한다. 주장은 교환에서 제외한다. 전역 최적·실제 경기력 동일을 보장하지 않는다. 평가 출처·표본·측정일이 다르면 비교의 한계가 있다.
- 자료가 전혀 없으면 균형 적용을 차단하고 단순 랜덤을 안내한다. 인원은 양 팀 선발 10명씩, 후보 포함 전체 인원 차이 최대 1명이다. 수비 위치는 무작위 초안이며 최적 포지션 추천으로 표시하지 않는다.

## 보존 및 백업

schema14, 저장 키, JSON 백업 구조, 선수·평가·경기 모델을 유지한다. 추가된 선택 상태와 비교값은 편성 화면에서만 사용하므로 마이그레이션이 필요하지 않다. 저장 시 기존 `Game.entry`, `lineups`, `rosters` 형식으로 새 경기를 추가한다. 과거 경기·평가·사진·규칙 설정을 수정하거나 미측정 값을 생성하지 않는다. 저장 실패 시 초안을 유지한다.

RULE01~08, TYPE1 10포지션/9능력/v2.0 가중치, 주루 40:60, 날짜별 평가 누적 계산은 변경하지 않는다. Supabase 연결 작업은 사용자 요청에 따라 계속 보류한다.

## 검증 범위와 남은 확인

가상 데이터만 사용해 단순 랜덤/균형, 주장 고정/해제/재추첨, 팀 슬롯, 타순·수비 수동 수정, 감독 확인, 경기 생성, 기존 형식 백업을 검증한다. 자동 테스트 수와 브라우저 결과는 [VALIDATION](VALIDATION.md)에 기록한다. iPad 크기 브라우저 검증과 실제 iPad Safari의 터치·키보드 검증은 구분한다. 실제 수업 자료의 평가 출처 선택과 균형 결과의 타당성은 감독이 확인한다. 공식 종합 선발 배점은 계속 미확정이며, 영구 주장 직책 관리와 최적화 보장은 이번 범위에 포함하지 않는다.
