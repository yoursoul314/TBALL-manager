# BETA 0.14.2 — 평가목적 기본 선택과 마지막 평가자 기억

## 동작

- 새 타격 날짜는 타격 평가, 새 수비 날짜는 수비 평가를 기본 선택한다. 터치 선택/직접 입력으로 변경할 수 있으며 새 날짜마다 화면의 목적 기본값으로 돌아온다.
- 새 타격·수비·펑고 날짜에서 선택한 평가자를 다음 날짜에 기본 적용한다. 등록 후 최초 선택이 필요하며 이후 새로고침에도 유지된다. 다른 이름을 터치하면 마지막 값이 갱신된다.
- 사용 중지되거나 현재 등록 명단에 없는 ID는 자동 선택하지 않는다. 기존 기록의 평가자, 삭제/정정 확인 처리자는 자동 변경하지 않는다.

## 저장 보존

기기 UI 설정 키 tb-manager.last-assessor.v1에는 등록 ID 문자열만 기록한다. 평가 본문/수정 이력에 이름을 복제하거나 저장 리비전을 변경하지 않는다. schema13 및 JSON 백업 형식을 유지하며 이 기기 선호값은 JSON 평가 백업에 포함하지 않는다. preview=1에서는 sessionStorage만 사용한다.

저장 공간이 부족하면 현재 선택은 유지하고 기억 실패를 표시한다. 실제 평가 저장을 막지 않는다. 기록 초기화는 명단과 선호값을 유지하며 명시적 전체 초기화는 이 키도 제거한다. 전체 초기화가 실패하면 기존 원본과 선호값을 함께 복구한다.

## 변경 및 검증

assessmentPreferences.ts, AssessorPicker, BattingDayView, DefenseDayView, FungoView, repository.resetAll, 버전/문서 및 QA를 변경했다. 경기 규칙·TYPE1 가중치·평균 계산은 변경하지 않는다.

AssessmentDefaults.test.tsx는 화면별 목적/평가자 변경·재마운트, 과거 기록 보존, 사용 중지/없는 ID, 기존 기록·처리자 구분, 기억 저장 실패, 전체/기록 초기화, 미리보기 분리를 검증한다. scripts/assessment-defaults-qa.cjs는 가상 학생만 사용하는 독립 WebKit iPad 환경에서 기본값→날짜 저장→평가자 변경→재로딩→사용 중지→저장 실패→가로/세로 레이아웃을 확인한다. 실제 아이패드 자체의 자료는 접근하거나 변경하지 않는다.

최종 검증 결과: npm run check의57파일298테스트 및 빌드 통과. 로컬 WebKit 가로/세로4개 종합 흐름 통과, 페이지 오류0건. 공개 배포 검증은 별도 릴리스 보고서에 기록한다.

## 수비 학생별 연속 평가

DefenseAssessmentPanel의 저장 버튼을 통합했다. 할당 횟수가 남아 있으면 같은 학생의 다음 상황을 기록하며, 마지막 회차가 성공적으로 저장된 뒤 다음 학생으로 이동한다. 마지막 회차에는 다음 학생이 있을 경우 버튼에 ‘다음 학생’을 표시한다. 마지막 학생은 완료 상태로 유지하고 추가 저장을 차단한다.

DefenseAttemptPlan에 남은 횟수를 표시한다. 이전 기록의 목표 null은 보존하며 자동 이동하지 않는다. 취소한 상황은 횟수에서 제외하고 보충 기록으로 목표를 채워야 이동한다. 정정·취소 자체는 이동하지 않는다. 기존 학생 직접 선택/이전·다음 버튼과 미저장 보호를 유지한다.

DefenseDayComparison/DefenseSequence/TabletAssessment 테스트 및 scripts/defense-sequence-qa.cjs로 학생별2~3회 할당, 마지막 회차 저장 실패, 마지막 학생, 정정·취소·보충, 목표 미설정, 원본 보존을 검증한다. 기존 비교/태블릿 QA는1회 계획을 명시하고 통합 저장 버튼을 사용하도록 조정했다.
