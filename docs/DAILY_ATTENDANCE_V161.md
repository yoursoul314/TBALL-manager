# 일별 전체 출석부 · BETA 0.16.1

## 사용 방법

1. 수업 출석부에서 날짜를 고르면 등록 학생 전체가 학년·반·번호 순으로 나타난다. 학급을 하나씩 추가할 필요가 없다.
2. 학생 행의 미확인 / 출석 / 결석 / 지각 / 조퇴 / 활동 제한을 누르면 즉시 저장한다.
3. 여러 학생의 왼쪽 체크박스를 선택하고 일괄 출결 버튼을 누른다. 머리글 체크박스는 현재 표시된 명단만 선택한다.
4. `표시 명단의 미확인 학생 모두 출석`은 이미 기록한 결석·지각·조퇴·제한을 바꾸지 않는다.
5. 학생 찾기·학급·출결 필터는 조회 범위만 좁힌다. 조건이나 날짜를 바꾸면 선택을 해제해 숨겨진 학생을 잘못 처리하지 않는다.
6. 출결을 아직 체크하지 않고 명단만 저장하려면 `전체 명단 반영`을 누른다. 단순 날짜 조회는 저장하지 않는다.
7. 변경 이력을 펼쳐 정정을 확인한다. 최근 50건부터 이전 이력을 추가로 조회할 수 있으며 원본 이력 전체는 보존한다.

## 화면 및 참고 자료

[나이스 2025년 상반기 특수학교 사용자 설명서](https://cdn.neis.go.kr/edu/2025%EB%85%84_%EC%83%81%EB%B0%98%EA%B8%B0_%ED%8A%B9%EC%88%98%ED%95%99%EA%B5%90%EC%9A%A9_%EB%82%98%EC%9D%B4%EC%8A%A4_%EC%82%AC%EC%9A%A9%EC%9E%90_%EC%84%A4%EB%AA%85%EC%84%9C_%28%EC%95%88%EB%82%B4%EC%9A%A9%29.pdf)의 일일출결관리 안내에서 날짜와 학생 명단을 중심으로 입력하는 방식을 참고했다. TB Manager는 날짜 선택 → 전체 명단의 출결 칸 터치 → 자동 저장 흐름을 사용한다. 나이스 연동이나 공식 생활기록부 출결 처리는 구현 범위가 아니다.

아이패드 크기에서는 날짜·요약·검색·일괄 처리 영역을 유지하고 명단 안에서 세로로 스크롤한다. 표 머리글은 고정하며 행 버튼과 선택 영역은 최소 48px이다. 학생이 선택되면 일괄 버튼이 나타나고 완료 후 접혀 명단 공간을 확보한다. 작은 휴대전화에서는 표의 가로 스크롤을 허용한다.

학급 N개를 준비할 때 종전의 `학급 선택 + 명단 추가` 2N회가 없어졌다. 전체 미확인을 출석으로 처리하는 데는 날짜 선택 후 1회 터치다. 예외 학생 K명은 개별 칸 K회 또는 체크 K회 + 일괄 상태 1회로 처리할 수 있다.

## 저장·백업 호환성

- schema16, 기존 저장 키, ClassDay와 history 구조를 그대로 사용한다. 별도 이전이나 데이터 덮어쓰기가 없다.
- 기존 날짜는 원래 ID·생성일·이름·학년·반·번호·출결·이력을 보존한다. 해당 날짜에 없던 등록 학생만 미확인으로 추가 준비한다.
- 저장된 과거 출석부의 삭제 선수 행은 보존한다. 새 날짜에는 삭제 선수를 포함하지 않는다. 출전 불가 선수도 출석 여부를 자동 판단하지 않는다.
- 과거 날짜에 전학·학적 변경이 있었는지는 자동 추정하지 않는다. 기존 학적 스냅샷은 유지하며 새로 추가한 학생은 미확인으로 검토한다.
- 다른 날짜의 출결을 복사하지 않는다. 조회만으로 저장 용량을 사용하지 않는다.
- 저장 실패 시 출결을 화면에 확정하지 않고 선택한 학생을 유지한다. 재시도 시 이력이 중복되지 않는다.
- 기존 경기의 출석 스냅샷은 바꾸지 않는다. 새 경기의 누락 검사 범위는 여전히 감독이 선택한 수업 학급이며, 전체 출석부의 모든 학생을 한 경기에 넣지 않는다.
- 기존 JSON 백업을 읽고 같은 schema16으로 내보낼 수 있다. 선수·평가·경기·사진 구조와 RULE01~08, TYPE1 v2.0, 주루 40:60은 변경하지 않는다.

## 검증 및 남은 범위

실제 iPad Safari의 날짜 선택기·터치 스크롤은 기기에서 추가 확인이 필요하다. 교시별 출결, 질병/인정 사유, 나이스 연동, 서버 동기화는 이번 범위에 포함하지 않는다.

검증 결과 (2026-11-16): `npm run check` 통과 — 80개 파일, 427개 테스트(신규 14개 포함), 타입 검사·프로덕션 빌드 성공. 세로 화면 보완 후 최종 빌드도 통과했다. RULE 설정과 TYPE1 v2.0 설정 파일의 해시는 변경 전과 일치한다. 자동 검증에는 기존 일부 학급 데이터 병합, 이전 출결·학적 스냅샷 보존, 저장 실패와 재시도, 날짜 전환, 선택·검색·필터 범위, 기존 JSON 백업 복원, 경기 수업 범위 검증을 포함한다.

격리된 가상 데이터 검증 탭에서 24명 전체 표시 → 2명 결석 → 미확인 22명 출석 → 다음 날짜 미확인 24명 → 이전 날짜 원래 상태 → 새로고침 후 출석 22명·결석 2명 유지 순서를 확인했다. 1024×768, 768×1024, 1366×900에서 페이지와 명단의 가로 넘침이 없고 주요 출결 버튼이 48×48px 이상임을 확인했다. 768px에서는 메뉴를 접어 모든 출결 열이 보이게 한다. 실제 학생 데이터는 수정하지 않았다. 화면 증빙은 로컬 `work/v161-ui/landscape.jpg`, `portrait.jpg`에 보관하며 저장소에는 포함하지 않는다.
