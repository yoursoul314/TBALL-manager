# 경기 직접·랜덤 구성 · BETA 0.15.1

## 사용 순서

1. 경기 기록실 → 새 경기 → 날짜·선공 팀·후공 팀 설정.
2. **직접 구성**(기본): 기존 등록 선수 불러오기, 학년·반 필터, 일괄 선택, 선발·교체 후보 배정, 감독 승인 배치안 적용을 사용합니다.
3. **랜덤 구성**: 학년·반·검색으로 참가 학생을 선택합니다. 검색 결과 선택은 현재 보이는 학생을 기존 선택에 추가합니다. 필터 밖 선택 인원도 표시하며 선택 해제로 전체 선택을 비울 수 있습니다.
4. 출전 가능한 학생 20명 이상을 선택하고 **랜덤 구성 적용**을 누릅니다. 기존 학생의 소속 팀과 관계없이 이 경기 안에서만 배정합니다.
5. 양 팀 선발은 각 10명, 남은 학생은 교체 후보로 고르게 배정합니다. 후보가 홀수이면 어느 팀에 한 명을 더 배정할지도 무작위입니다. 선발 타순과 TYPE1 10개 수비 위치도 무작위 초안으로 배치합니다. 평가 점수·희망 포지션에 따른 실력 균형은 계산하지 않습니다.
6. 선공·후공 엔트리 탭에서 타순·수비를 조정합니다. 직접 구성으로 전환하면 개별 선수와 경기 상태를 수정할 수 있습니다. 모드 전환만으로 편성을 초기화하지 않습니다.
7. **랜덤 구성 적용**으로 재추첨하거나 **이전 편성으로 되돌리기**로 바로 이전 초안을 복구합니다. 수동 편성/타순/수비/팀을 수정하면 이전 초안 되돌리기는 종료됩니다. 매번 편성을 바꾸면 감독 확인이 해제됩니다.
8. 감독 별칭 입력 → 양 팀 엔트리 확인 → 경기 생성. 저장 실패 시 입력과 편성을 유지합니다.

## 보존·검증 계약

- Fisher–Yates 셔플과 순차 교대 배정으로 학생 누락·중복 없이 분할합니다. 모든 참가자가 선발 또는 교체 후보에 포함됩니다.
- 삭제·출전 불가 선수와 어느 한 팀에서 결석·출전 불가로 지정한 학생은 후보 목록과 도메인 검증에서 제외합니다. 직접 구성에서 상태를 수정한 뒤 다시 선택할 수 있습니다.
- 양 팀이 같거나 고유 참가자가 20명 미만이면 적용하지 않습니다. 중복 ID는 한 명으로 계산합니다.
- 기존 초안을 교체할 때 선택하지 않은 기존 선발·후보는 원래 편성 팀의 미출전 상태로 남습니다. 결석·출전 불가 기록은 보존합니다.
- 초안만 React 상태에서 변경하고 생성 시 기존 Game/entry 스냅샷으로 저장합니다. 별도 schema migration은 필요하지 않습니다. schema14·JSON 백업 호환성·localStorage 저장 키를 유지합니다.
- 선수 공통 명단·사진·평가·기존 경기·원본 이벤트는 변경하지 않습니다. 새 경기 생성 후 원본 보존, 재로딩, JSON 백업 복원을 테스트합니다.
- 최종 생성에는 감독 확인이 필요하며 RULE01~08, TYPE1 v2.0 가중치, 기존 평가 계산을 변경하지 않습니다.
- Supabase 개설·연결은 사용자 요청으로 보류했습니다. 랜덤 편성은 서버가 필요하지 않습니다.
